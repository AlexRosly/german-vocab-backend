# Справочник глаголов — 15.11.2026

Отдельный раздел «Глаголы» использует существующие `word_verb_forms`. Формы не копируются в отдельный справочник; изменений схемы, миграций и записей в рабочую БД в этом этапе нет.

## Пользовательский сценарий

- По умолчанию показаны все опубликованные карточки глаголов; можно выбрать только глаголы личного словаря.
- Поиск работает по немецкому слову, Präteritum и Partizip II, без учёта регистра. Например, `ging` и `gegangen` находят соответствующий глагол.
- Фильтр haben/sein выбирает карточки с таким вспомогательным глаголом. В таблице остаются все варианты найденной карточки, чтобы различия значений не терялись.
- Таблица: Infinitiv / Präteritum / Partizip II / Perfekt; рядом перевод выбранного языка, пояснение варианта и принадлежность личному словарю. Отсутствующий перевод не подменяется русским. Личный перевод видит только владелец.
- Нажатие на инфинитив открывает окно с формами, общей заметкой и примерами. «В справочник глаголов» из словаря, библиотеки или модерации сразу открывает нужную карточку в этом разделе.
- На телефоне строки становятся вертикальными карточками с подписями полей. Закрытие окна и Escape возвращают фокус к вызвавшей кнопке либо к заголовку справочника при переходе из другого раздела.

## API

Все маршруты требуют AuthGuard и отвечают `Cache-Control: no-store`.

- `GET /api/v1/verbs/config` — прежние `enabled`, `version:1` плюс `catalog:true`. Старые клиенты совместимы. Frontend показывает новый раздел только при этой возможности; старый backend не получает неподдерживаемые запросы справочника.
- `GET /api/v1/verbs?q=ging&scope=library&auxiliary=SEIN&page=1`. `q` — до 100 символов, NFC/trim; `scope=library|mine`, по умолчанию library; `auxiliary=HABEN|SEIN` или параметр отсутствует; `page` — целое 1–1000000. Фиксировано 30 карточек на страницу, сортировка german/id. Ответ `{items,total,page,pageSize:30,hasNext}`. Count и page читаются в RepeatableRead. Вне диапазона возвращается пустая страница; frontend возвращается к последней доступной странице, если каталог сократился.
- `GET /api/v1/verbs/:id` — одна доступная карточка с формами. Нет карточки, нет форм или нет доступа → 404. Примеры читаются прежним защищённым `GET /words/:id/examples`.

В `library` даже ADMIN не видит чужие неопубликованные карточки. В `mine` видны только связи пользователя и доступные ему карточки (опубликованные либо созданные им). По прямому ID действуют существующие правила чтения: USER — опубликованная/своя, ADMIN — также карточка на модерации. В выдаче нет сырых userWords/чужих личных переводов/ID автора. Личный перевод применяется через существующий PersonalTranslationsService с ограничением по пользователю, языку и его словарю. Принадлежность словарю возвращается одним boolean.

## Проверки и выпуск

97 тестов words, включая новые HTTP-проверки auth/доступов/разных словарей/личных переводов/отсутствия подстановки RU/форм/auxiliary/пагинации/отсутствия записей; backend build. Frontend: 165 клиентских тестов, lint, production build из изолированного снимка без посторонних изменений верстки владельца. Скомпилированный сервис проверен на настоящей Neon только чтением: 613 опубликованных карточек, разные страницы, поиск по форме, haben/sein, прямой ID, пустой посторонний словарь. Браузерные проверки используют синтетический mock API, не реальные аккаунты.

Код → Git main → Netlify. Для включения раздела владелец обновляет backend на VPS под `wortkarten`: git pull --ff-only, npm run build, pm2 restart wortkarten-api. При необходимости установить dev-зависимости — npm ci --include=dev. Миграция форм уже выполнена в предыдущем этапе, повторять её или импорт не нужно. После обновления backend обновить страницу сайта.

Следующий согласованный этап — осмысленные сочетания существительных с существующими глаголами, с готовой фразой/предлогом/падежом и переводом. В этом выпуске эти связи не реализуются.
