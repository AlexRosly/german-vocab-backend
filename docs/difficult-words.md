# Личные трудные слова

Реализовано 20.11.2026. Это ручная личная отметка, независимая от избранного, архива и оценки ответа. Снятие отметки тоже ручное; успешная тренировка её не очищает. Другая учётная запись не видит и не меняет эту отметку.

В карточке — «Отметить трудным» / «✓ Трудное», в разделе словаря — «Трудные слова», в тренировке — «Тренировать трудные». Очередь учитывает текущие поиск, книгу, урок, уровень, артикль и допустимость слова для выбранного режима. Архив исключён из тренировок; при архивировании отметка сохраняется. Ответы используют существующий общий SRS без изменения алгоритма. Автоматическое определение трудных слов, отдельная просроченная очередь, дневные лимиты и аналитика по режимам остаются следующими задачами.

## API и CSV

`UserWord.isDifficult` — boolean по умолчанию false. Только `/words/mine` и личный `/words/:id/dictionary-settings` возвращают флаг. PUT принимает необязательный boolean `isDifficult` с прежней обязательной revision. Обновление ограничено собственной записью и текущей revision, конфликт даёт 409. Администратор тоже не меняет чужие личные отметки. Обычные операции избранного/архива не сбрасывают отметку.

В полном CSV добавлена необязательная колонка `is_difficult` (строго true/false). Фиксированный шаблон из 20 колонок не изменён. CSV/XLSX без новой колонки и сохранённые ранее планы импорта совместимы. Новая личная привязка получает переданный флаг или false; существующая сохраняется, отличие отражается предупреждением `dictionary_flags`. Общие карточки не перезаписываются. Формат экспорта остаётся v1 с необязательной колонкой.

## Выпуск

Нужна миграция `20261120120000_add_dictionary_difficult_flag`: один `ALTER TABLE user_words ADD COLUMN isDifficult BOOLEAN NOT NULL DEFAULT false`. Перед применением к рабочей Neon требуется отдельное согласие владельца по AGENTS.md. После отдельного согласия владельца миграция применена к рабочей Neon 20.11.2026 в 09:16 UTC. Перед применением свежая копия всех 24 таблиц восстановлена и проверена. После применения все прежние колонки данных 23 таблиц приложения и прежняя история миграций неизменны; у 5389 личных записей новый флаг false. Сохранены 3773 слова, 388 записей прогресса и 1285 ответов. Ожидаются обновление VPS владельцем и публичная приёмка.

Порядок: согласие → миграция рабочей БД → обновление backend на VPS (git pull, npm ci, npm run build, перезапуск существующего wortkarten-api) → приёмка Netlify. Сначала миграция, затем новый backend: он запрашивает новое поле. Frontend со старым API скрывает новые элементы, пока API не возвращает boolean isDifficult. Откат приложения — на прежнюю версию backend/frontend, поле можно оставить; удалять его для отката не требуется.

## Проверки

149 words-тестов backend, 185 auth/study/moderation/languages-тестов, 213 клиентских тестов, lint и обе production-сборки прошли на отдельных копиях исходников. Настоящий Prisma на восстановленной копии проверил личные права, конфликт revision, сохранение архива/избранного, CSV-цикл и старый план импорта. У всех прежних строк 24 таблиц сохранены все старые колонки, новый флаг false. Свежая приватная резервная копия хранится вне Git.

Браузер использовал только синтетический API: сохранение/перезагрузка отметки, фильтр, очередь по режиму, правильный/ошибочный ответ и одна сохранённая тренировка, архивирование/возврат, 409 без автоповтора, успешное снятие после обновления, скрытие фичи на старом API. Мобильные ширины 320/390 без горизонтального переполнения. Это локальная проверка, не приёмка рабочей Neon или iPhone.
