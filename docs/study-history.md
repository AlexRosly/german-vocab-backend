# Персональная история тренировок

01.11.2026. Новые маршруты `/api/v1/study/history` требуют Bearer-сессию,
берут userId только из AuthGuard и возвращают `Cache-Control: no-store`.
ADMIN также видит только свою историю. Чтение не меняет WordProgress/SRS.
Схема и миграции не меняются; Neon этим этапом не затрагивается.

## Страницы

`GET /study/history?limit=20&cursor=...` возвращает
`{ sessions: [...], nextCursor: string | null }`.
limit: целое 1–50, по умолчанию 20; неизвестные query-поля запрещены.
Каждая запись: id, totalWords, knownCount, needsReviewCount, startedAt,
completedAt. В списке нет карточек, идентификатора владельца или переводов.
SQL-запрос выбирает максимум limit+1 записей и только эти поля.

Порядок: startedAt DESC, id DESC. nextCursor — непрозрачная позиция страницы;
клиент передаёт её без изменений. Позиция содержит дату и id последней записи,
но не даёт доступа к чужому аккаунту. Следующая страница выбирает записи строго
ниже позиции; удаление опорной записи не ломает чтение. Новые тренировки выше
позиции появляются при обновлении первой страницы. Формат/длина курсора и ISO
дата проверяются, неверный курсор даёт 400. Общее количество не вычисляется.

## Одна тренировка

`GET /study/history/:id` возвращает собственную сессию и ответы words.
Несуществующая и чужая сессия одинаково возвращают 404. Чтение деталей —
транзакция RepeatableRead, чтобы поля карточек и проверка видимости относились
к одному снимку. Снятие UserWord не уничтожает историю. Опубликованные или
созданные владельцем сессии слова доступны; чужое слово, ставшее приватным,
скрывается полностью вместе с вложенными идентификаторами ответов/слов.
Исходные итоговые счётчики сохраняются: видимых деталей может быть меньше.
selectedTranslation соответствует текущему translationLanguage, без RU fallback.

Ответы — сохранённые KNOWN/NEEDS_REVIEW, формы и переводы карточек — текущие.
Это не снимок текста карточек на момент обучения. Даты существующей модели
создаются при сохранении сессии; по ним нельзя вычислять длительность тренировки.

Старый `GET /study/sessions` остаётся совместимым массивом; новый UI использует
ограниченный список и отдельные детали, не загружая все карточки истории сразу.

## Проверка

`npm run test:study`: 43 теста, включая 8 новых HTTP/сервисных сценариев истории;
`npm run test:languages`: 34 теста; `npm run build`.
Проверены авторизация, изоляция USER/ADMIN, одинаковые даты, границы страниц,
удалённая опорная запись, новые вставки, валидация, приватные карточки,
удалённая связь, selectedTranslation и неизменность прогресса.
Тесты используют полный AppModule с подменой Prisma; реальные SQL/конкурентность
PostgreSQL этим не проверяются.
