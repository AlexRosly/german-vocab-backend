# Личные заметки к словам

GET/PUT `/api/v1/words/:id/personal-note` требуют AuthGuard. userId берётся только
из CurrentUser, а не из тела/query. Даже ADMIN читает/меняет только свою заметку.
Доступ требует активную UserWord и опубликованное либо созданное вами слово.
Одинаковый 404 скрывает отсутствующие/недоступные карточки.

GET возвращает `{ wordId, text, revision }`, отсутствие — null/null.
PUT принимает `{ text, revision }`: text — строка до 2000 Unicode-символов после
очистки внешних пробелов и перевода CRLF/CR в LF. HTML остаётся обычным текстом.
Пустой текст удаляет только собственную заметку. revision обязательна: null для
создания/отсутствия, строка из GET для правки/очистки. Лишние поля запрещены.
В ответе только wordId/text/revision, Cache-Control no-store.

Чтение и запись используют Serializable через существующий WordAccessService,
с повтором конфликтов P2034/P2002. Проверка связи/видимости и заметка относятся
к одной транзакции. Сохранение/очистка сравнивает revision; updateMany/deleteMany
также условны по userId/wordId/revision. Устаревшая версия даёт 409 без перезаписи.
Каждая непустая запись получает новую случайную UUID-ревизию, поэтому старый
редактор не перезапишет заметку после удаления и повторного создания.

Миграция `20261101220000_add_personal_word_notes` добавляет отдельную таблицу
с составным PK userId/wordId, индексом wordId и FK к users/words. FK к UserWord
намеренно нет: отвязка личного словаря сохраняет заметку, повторное добавление
возвращает доступ. Если чужая карточка стала приватной, чтение/правка запрещены
до восстановления её доступности. Удаление самого User/Word каскадно удалит
связанные заметки; текущая операция «Убрать из словаря» Word не уничтожает.

Общая Word.notes не переносится и не меняется. Нет личных заметок в глобальном
WORD_INCLUDE, библиотеке, деталях общей карточки, модерации или SRS. Сохранение
не меняет Word.updatedAt/публикацию/переводы/прогресс/историю. Поиск по личным
заметкам не добавлялся. Prisma 6.19.3 и зависимости сохранены.

Проверки: 42 words-теста (9 новых), 38 moderation-тестов, build. HTTP использует
полный AppModule с mock Prisma, не PostgreSQL. Покрыты USER/ADMIN и разные
аккаунты, неопубликованная собственная карточка, отсутствие связи, скрытая
приватная карточка, валидация/инъекции, очистка, конфликт, повторное создание,
сохранность при отвязке/возврате и отсутствие утечки в общие ответы.

Перед Deploy backend требуется миграция в согласованной демо-БД. Build/start
не применяют миграции. Основную Neon main не менять без отдельного согласия.
