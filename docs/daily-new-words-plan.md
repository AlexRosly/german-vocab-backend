# Личный дневной план новых слов

Решение владельца 20.11.2026: число новых слов задаёт пользователь; после достижения можно продолжать без блокировки. Повторения не ограничиваются. Отдельная настройка `newWordsDailyGoal` от 1 до 500, по умолчанию 10, хранится на пользователе. Прежняя общая `dailyGoal` и выбор 5/10/20/всех слов на одно занятие сохранены независимо.

В Настройках — «Новых слов в день — ваш план». В тренировке — дневной счётчик, остаток и дополнительная кнопка «Изучить по плану»: она берёт минимум остатка плана, выбранного размера занятия и доступной текущей очереди новых слов. Обычная кнопка новых слов доступна всегда, после выполнения подписана «Продолжить новые слова». Все остальные тренировки также доступны. Ни серверного запрета, ни сброса SRS нет. Перед запланированным стартом серверный счётчик перечитывается; если план уже выполнен, показывается сообщение с возможностью обычного запуска.

`GET /study/progress` добавляет `newWordsDailyGoal` и `newWordsStudiedToday`. Считается первый сохранённый ответ на слово у этого пользователя в любом режиме (MIN answeredAt по wordId в его сессиях). Повторные ответы и идемпотентный повтор не увеличивают число. Дата — календарные сутки аккаунта с учётом часового пояса; будущие ответы исключены. Архивирование/снятие из словаря не отменяет уже выполненную за день работу. Это число первых ответов в сохранённой истории, а не оценка знания слова; отсутствующую старую историю не выдумываем. Общий счётчик studiedToday имеет прежнее значение и не подменяется новым.

`GET/PATCH /users/me/preferences` поддерживает необязательный новый integer; DTO и сервис отклоняют null/строки/дроби/значения вне 1–500. Обновление одной настройки не меняет остальные и ограничено текущим пользователем. Frontend со старым API скрывает новые настройки/счётчик/кнопку плана и сохраняет старое поведение. Пароли/токены/роли не добавляются в настройки.

## Миграция и выпуск

Нужна одна миграция `20261120150000_add_daily_new_words_goal`: добавляет в users NOT NULL INTEGER newWordsDailyGoal DEFAULT 10. Слова, примеры, история, прогресс и прежние настройки не переписываются. Проверена свежая приватная копия всех 24 таблиц восстановлением и сравнением хешей старых колонок после миграции. После отдельного согласия владельца миграция применена к рабочей Neon 20.11.2026 в 18:04 UTC. Перед применением свежая копия всех 24 таблиц восстановлена и проверена; после него все старые колонки 23 таблиц приложения и прежняя история миграций неизменны. Сохранены 3773 слова, 5389 записей словаря, 449 записей прогресса и 1346 ответов. У семи пользователей новый план равен 10. Ожидаются обновление backend на VPS владельцем и публичная приёмка. Обновление backend (git pull, npm ci --include=dev, npm run build, перезапуск wortkarten-api). Netlify получает frontend через Git. Откат кода не требует удаления поля.

## Проверки

338 backend-тестов auth/words/study/moderation/languages и 222 клиентских, lint и обе сборки прошли. Два прежних набора были повторены после обновления тестовых пользователей/ожидаемого ответа новым полем; приложению это исправление не меняло логику. Настоящий Prisma на восстановленной локальной БД подтвердил первый ответ/владельца/архив/идемпотентность, свободное превышение плана и сохранность первоначальных строк всех 24 таблиц. SRS не менялся. Рабочая БД для этих проверок только читалась резервным копированием.

Браузер на синтетическом API: сохранение 2 новых слов в настройках, запуск остатка 1, результат 2 из 2, дополнительное занятие и сохранённый результат 3 из 2; изменение плана на 5, повторная серверная сверка с уже выполненным планом не запускает устаревшую очередь; старый API скрывает новую настройку. 390/320 px без горизонтального переполнения. Это не публичная приёмка Neon/VPS/Netlify.
