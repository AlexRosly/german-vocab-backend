## Контракт

Миграция `20261115120000_add_word_verb_forms` добавляет `VerbAuxiliary` (`HABEN`, `SEIN`) и таблицу `word_verb_forms`. На карточку допускается до четырёх упорядоченных вариантов. Каждый хранит `praeteritum`, `participle2`, `auxiliary`, `reflexive`, необязательное `usage`. CHECK/FK/unique ограничивают позицию, пустые формы, принадлежность слову и повторную позицию.

Наличие форм означает явное указание «это глагол»; отсутствие артикля само по себе ничего не классифицирует. Формы общие для карточки, не копируются в личные словари. Различные вспомогательные глаголы или значения хранятся отдельными вариантами, чтобы не перемешать пары.

`POST /words` и `PATCH /words/:id` принимают:

```json
{
  "german": "gehen",
  "article": "none",
  "grammaticalNumber": "not_applicable",
  "isVerb": true,
  "verbForms": [{
    "praeteritum": "ging",
    "participle2": "gegangen",
    "auxiliary": "SEIN",
    "reflexive": false,
    "usage": null
  }]
}
```

Формы указываются для `er/sie/es`. У глагола нельзя одновременно указать артикль/множественное число. Объявление `isVerb:true` без полного варианта отклоняется. При обычном PATCH без новых полей прежние формы сохраняются; `isVerb:false` явно снимает классификацию и убирает формы. Пустой `verbForms:[]` без явного снятия классификации отклоняется. Права те же, что у общей карточки: автор своих неопубликованных; ADMIN всех. Новые карточки отправляются на модерацию и добавляются в словарь автора.

`GET /verbs/config` требует авторизации и возвращает `{enabled,version:1}`. До готовности backend frontend скрывает новые поля и не отправляет их старому API. Формы видны в словаре, библиотеке и проверке модерации; снимок ревизии модерации учитывает их. Снимки предложений исправлений учитывают непустые формы; прежние снимки обычных слов совместимы.

## Импорт новых партий после согласования

Импортёр не меняет строки `words`, публикацию, переводы, примеры, связи, пользовательские словари или прогресс. Он проверяет ID, точное немецкое слово, категорию и время изменения из инвентаризации. Отличающиеся существующие формы или изменившаяся карточка останавливают всю транзакцию. Повторный запуск с совпадающими формами ничего не перезаписывает. По умолчанию выполняется только чтение.

```bash
# Значения HOST и SHA256 берутся из проверенного окружения и файла, не из чата с секретами.
node --env-file=.env scripts/import-verb-forms.cjs \
  --file data/verb-forms-20261115.json --expect-host "$HOST" --expect-sha256 "$SHA256"
# Только после проверки dry-run и согласования рабочей БД — тот же вызов с --apply.
```

Первая партия уже загружена, повторять её не требуется. Перед новой рабочей операцией нужна свежая копия схемы/данных. После миграции backup-database.cjs включает новую таблицу; VPS pg_dump сохраняет её автоматически.
