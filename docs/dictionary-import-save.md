# CSV: выбор и сохранение пакета

Этап R09: CSV можно проверить, выбрать действия, подтвердить пакет, сохранить и получить отчёт. XLSX и произвольное сопоставление колонок пока не реализованы. Основа — [предпросмотр](dictionary-import-preview.md) и [CSV-контракт](dictionary-csv.md).

## Пользовательский сценарий

1. Настройки → выбрать CSV по нашему шаблону → «Проверить совпадения». Предпросмотр по-прежнему ничего не записывает.
2. Новые слова получают действие создания; существующие — ссылку на найденную карточку; повторы файла — ссылку на предыдущую запись; ошибки — пропуск. Неоднозначные записи требуют выбора. Через «Показать все решения» можно изменить действия остальных записей.
3. Можно выбрать опубликованную/свою карточку, предыдущую запись того же слова, пропуск или явно отдельное значение. Для отдельного значения нужен перевод; совпадение значения с доступной карточкой отклоняется. Среди показанных до пяти кандидатов нельзя угадывать нужный смысл: если его нет, пропустить запись и уточнить её в библиотеке.
4. «Подготовить сохранение» сохраняет приватный план, без изменения словаря. В модальном окне видны количества новых/существующих/объединяемых/пропущенных и предупреждения о личных отличиях.
5. После «Подтвердить и сохранить» сервер обрабатывает до 25 записей за одну транзакцию. Отображаются прогресс и итоговые счётчики. «Приостановить» прерывает ожидание/следующие запросы; уже отправленная порция может завершиться. «Продолжить импорт» сначала читает сохранённый курсор, затем продолжает. Подготовленный пакет также восстанавливается после reload; без browser storage сервер находит последний активный пакет этого аккаунта.
6. Отчёт хранит результаты каждой записи; UI показывает суммарные количества и первые 25 записей с личными отличиями. Нужное старое личное значение не заменяется. После завершения «Открыть обновлённый словарь» перезагружает актуальные карточки. Закрытие/истечение пакета не удаляет уже добавленные слова.

## Что записывается

- Новая общая карточка — всегда **PENDING_REVIEW**, в том числе при CSV обычного ADMIN-аккаунта. Немецкий текст, артикль/число, все переводы, до 20 примеров, до четырёх вариантов глагола, источники/уроки и общая заметка проходят текущие правила карточки. Пустой уровень остаётся null.
- Существующая карточка получает только личную привязку. Общие тексты, переводы, примеры, формы и источники не редактируются через импорт; новые отличающиеся общие материалы из файла к ней не дописываются. Это явно указано перед подтверждением. Для общих исправлений есть отдельный процесс предложений/ADMIN.
- Личные заметки/переводы добавляются только при отсутствии значения. Отличающиеся существующие значения остаются и отмечаются в отчёте. Лимит личной заметки исправлен на фактические 2000 символов, совпадающие с БД и ручным редактором.
- Архив/избранное задаются из файла только для новой личной привязки. Существующие настройки и весь прогресс не изменяются. Импорт не вызывает StudyService и не создаёт ответы тренировок.
- Личные книги и уроки объединяются без удаления прежних; до 20 книг на слово. Уроки доступны фильтрам и показываются в «Мои книги». Удаление книги обычным редактором удаляет также её личные номера; номера оставленных книг сохраняются.
- В простом шаблоне source_book/lesson_number задают личный курс существующего слова. Номер без книги отклоняется при подготовке, а не теряется. В полном экспорте v1 эти колонки описывают общую карточку: личные данные берутся из personal_books_json и новой необязательной personal_book_lessons_json. Старые выгрузки из 58 колонок по-прежнему читаются; новые содержат 59.

## API и защита повторов

Все маршруты авторизованы и отвечают `Cache-Control: private, no-store`.

| Маршрут | Назначение |
| --- | --- |
| GET /dictionary-import/save-config | enabled только после наличия всех объектов миграции; до неё экспорт, предпросмотр и прежние операции продолжают работать |
| POST /dictionary-import/prepare | multipart: file + decisions (JSON); обязательный UUID Idempotency-Key; до 3 запросов/минуту на аккаунт |
| GET /dictionary-import/latest-batch | Последний свой активный пакет; 204 при отсутствии |
| GET /dictionary-import/batches/:key | Свой план/прогресс/отчёт; чужой ключ не раскрывается |
| POST /dictionary-import/batches/:key/apply | JSON {cursor}; до 120 запросов/минуту на аккаунт |
| POST /dictionary-import/batches/:key/discard | Закрыть приватный план, оставив сохранённые слова |

Ключ уникален по владельцу. Хеш файла и канонических решений связывает ключ с содержимым: другой файл/решения с прежним ключом дают 409. Повтор prepare возвращает прежний план/отчёт; повтор apply со старым курсором возвращает сохранённый прогресс без следующей порции. Порция, её результаты и курсор фиксируются атомарно; после потерянного ответа состояние читается с сервера.

На аккаунт — не более двух активных планов и десяти подготовленных пакетов за 24 часа. План действует сутки. Завершение сразу очищает payload строк/решений; истёкшие payload очищаются при старте процесса, затем ежечасно и при новой подготовке. Компактные receipts/хеш/сводка остаются для идемпотентности; связи с пользователем каскадные. В sessionStorage сохраняется только ссылка-UUID на пакет, отдельно по аккаунту; CSV, личные тексты и auth-токены туда не пишутся. Поздние ответы другого аккаунта отбрасываются.

При подготовке справочник и личные поля читаются пачками. На записи повторно проверяются доступ, лексическое слово, значение и ревизия выбранной общей карточки. Появившееся единственное точное совпадение может заменить создание на личное добавление; неоднозначное/изменённое совпадение останавливает порцию с 409. Более ранние завершённые порции сохраняются; новый предпросмотр не сбросит их данные.

Serializable и таблица word_lexeme_guards координируют импорты с ручным созданием, редактированием и модерацией. Ограждения берутся в сортированном порядке; конфликты P2034/P2002 и SQLSTATE 40001/40P01 повторяются ограниченно. Ключ различает исходные умлауты/ß; артикль, уже введённый в немецкое поле существительного, учитывается также при поиске. Неожиданные транзакционные ошибки становятся безопасным 503 без вывода содержимого CSV в exception logs. Операторские административные загрузки отдельными скриптами не следует запускать одновременно с пользовательскими импортами: они не являются частью HTTP-протокола ограждений.

## Миграция и совместимость

`20261118180000_add_dictionary_import_batches` выполняется в BEGIN/COMMIT:

- две новые таблицы: dictionary_import_batches и word_lexeme_guards;
- JSONB lessons с DEFAULT '{}' в personal_word_books;
- данные words, переводы, примеры, роли, аккаунты, привязки и SRS не переписываются.

Применение к основной Neon требует отдельного согласия по AGENTS.md. До него изменения проверяются только на локальной восстановленной копии. После разрешённой миграции владелец вручную обновляет VPS: git pull --ff-only → npm ci --include=dev → npm run build → pm2 restart wortkarten-api --update-env. Netlify обновляет frontend из Git. Дополнительных SMTP/Google/cron настроек нет.

Приватный backup CLI поддерживает обе версии списка таблиц (22/24) и берёт структуру фактического datasource, а не модели будущего релиза. Это исключает рассогласование backup до миграции и включает receipts после неё. Ночной Docker pg_dump/Drive/timer не перенастраивается. Проверка скачанного внешнего Drive-архива остаётся отдельной от локальных восстановлений.

## Проверки

Пройден реальный Prisma/SQL сценарий на отдельной восстановленной PGlite-копии: создание с примерами/формами, разные значения, повтор ключа и курсора, иной ключ того же слова, права владельца, stale/expiry, 27 записей с продолжением после первой порции, личные конфликты, книги/уроки, редактирование списка книг, повтор транзакции P2034 и безопасная обработка неожиданных ошибок. Миграция сохраняет все исходные колонки 22 таблиц; backup новой схемы восстановлен с совпадением хешей 24 таблиц. Подготовлена также полная выгрузка 3734 карточек.

Воспроизводимый тест находится в test/import-save.integration.cjs, стенд — test/fixtures/import-db. В отдельной папке стенда выполнить npm ci; задать WORTKARTEN_IMPORT_TEST_BACKUP с проверенной приватной копией текущих 22 таблиц; node server.mjs восстановит её только в память и применит новую миграцию. Затем после npm run build задать WORTKARTEN_IMPORT_TEST_URL=`postgresql://postgres:postgres@127.0.0.1:55439/postgres?sslmode=disable&connection_limit=1` и запустить `node test/import-save.integration.cjs`. Тест отказывает другому host/port/database и проверяет маркер изолированной схемы. Нужна свежая копия для каждого прогона; существующие тестовые записи не удаляются молча. Не передавать production URL. PGlite multiplexing не заменяет полноценный параллельный нагрузочный тест настоящего PostgreSQL: проверены сам протокол/SQL и ограниченный retry, а не эмуляция всех конкурентных расписаний.

В браузере с синтетическим USER и настоящим локальным SQL проверены все действия, блокировка до выбора спорного значения, модальное подтверждение, восстановление подготовленного пакета после reload, создание двух/привязка двух карточек и пропуск ошибочной, итоговые четыре слова, дополнительная личная книга/урок 7, сохранение отчёта после reload, ширины 320/390 без горизонтального overflow. Внешние auth/study endpoints этого стенда подменены; это не production-приёмка и не повторный тест Google или SRS.
