# Подготовка слов и пакетный импорт

02.11.2026. Локальный операторский инструмент `scripts/import-words.cjs` создаёт
новые карточки через существующий POST `/api/v1/words`. SQL напрямую не выполняет,
Prisma-схему и API не меняет. Новые слова принадлежат вошедшему аккаунту и получают
PENDING_REVIEW даже при импорте от ADMIN. Публикация остаётся отдельным действием
в модерации. Примеры создаются атомарно вместе с каждым словом существующим API.

## Что можно прислать для подготовки

Достаточно Excel со списком немецких слов. Тема, предполагаемый смысл, урок и
уровень помогают выбрать значения и примеры. Подготовка включает артикль/число,
множественное число, переводы выбранных языков, CEFR при наличии основания,
немецкие примеры и необязательные переводы. Неоднозначные значения выносятся на
проверку. Скрипт сам не угадывает лексику, не генерирует переводы и не читает XLSX.
Из исходного Excel ассистент готовит проверяемый JSON для текущего API.

`templates/wortkarten-words-template.xlsx` содержит два пустых листа с подсказками:
«Слова» и «Примеры». Данные со строки 7, 100 подготовленных строк можно расширять.
Примеры связаны по ID слова. Выпадающие списки: article, grammaticalNumber, CEFR;
урок — целое 1–10000. Текст немецких слов/переводов хранится как текст, не дата.
Файл можно не использовать: список одной колонкой также подходит. Общая заметка
идёт в Word.notes и после публикации относится к общей карточке; личные заметки
изолированы и не импортируются этим инструментом.

## Формат данных

См. `examples/import-words.example.json`. Это учебный пример, не исходный список
пользователя. Верхний уровень: `{ "schemaVersion": 1, "words": [...] }`.
Одна строка JSON — одна карточка/значение, от 1 до 1000 карточек, файл до 10 MiB.
sourceId необязателен; при отсутствии назначается row-0001 и далее. При передаче
он должен быть уникальным, длина 1–100, допустимы буквы/цифры/точка/подчёркивание/дефис.
Остальные поля ровно как CreateWordDto: german, article, grammaticalNumber,
pluralForm, level, lessonNumber, notes, translations и examples. Переводы ru/de/en/uk
и примеры необязательны; до 20 примеров на карточку. Для отсутствующего перевода
пропускайте запись языка. null удаляет перевод при редактировании и не нужен в
файле создания. Не передавайте userId, роль, публикацию, существующие id или личные
заметки. Вся партия проверяется реальным скомпилированным DTO до авторизации.

## Предпросмотр

Из папки backend, Node.js 22+ и установленные зависимости:

```powershell
npm run build
npm run import:words -- --input ./words.json --report ./import-report.json
```

Это offline preview: авторизации, запросов API и записи БД нет. Проверьте данные
JSON, нормализацию/ошибки и отчёт. Точные повторы карточки внутри файла помечаются
duplicate-in-file. Не меняйте JSON между preview и продолжением этой же партии:
отчёт привязан к отпечаткам содержимого и стабильным sourceId.

## Создание карточек после проверки

Пароль не передаётся аргументом команды, в JSON или .env репозитория. В PowerShell:

```powershell
$env:WORTKARTEN_IMPORT_EMAIL = Read-Host 'Email аккаунта Wortkarten'
$importPassword = Read-Host 'Пароль Wortkarten' -AsSecureString
$env:WORTKARTEN_IMPORT_PASSWORD = [System.Net.NetworkCredential]::new('', $importPassword).Password
try {
  npm run import:words -- --input ./words.json --report ./import-report.json --resume --apply --api https://german-vocab-backend-pxp3.onrender.com/api/v1
} finally {
  Remove-Item Env:WORTKARTEN_IMPORT_PASSWORD -ErrorAction SilentlyContinue
  Remove-Item Env:WORTKARTEN_IMPORT_EMAIL -ErrorAction SilentlyContinue
  Remove-Variable importPassword -ErrorAction SilentlyContinue
}
```

--apply обязателен для записи; --resume здесь продолжает ранее проверенный preview.
API должен использовать HTTPS (локальный HTTP разрешён только loopback), путь
/api/v1, без query/hash/credentials. HTTP-переадресации запрещены. Access token и
refresh cookie живут только в памяти; при 401 допускается один refresh и повтор
того же тела. После работы инструмент завершает собственный вход через logout;
при неподтверждённом logout сообщает об этом. Пароли/токены не пишутся в отчёт.

## Дубликаты, частичный результат и продолжение

Новые карточки создаются последовательно. Существующая серверная проверка точных
дубликатов сохраняется; это не fuzzy-поиск по одному написанию. Конфликт 409 с
wordId помечается duplicate. Такая карточка не правится, не объединяется и не
дополняется примерами; она также не добавляется автоматически в личный словарь.
Можно отдельно добавить опубликованное слово из библиотеки.

Отчёт записывается атомарно перед POST и после результата. Поля: sourceId,
отпечаток, слово/артикль, state, при известном результате wordId/HTTP status.
Не копирует большой payload примеров; исходный JSON храните рядом отдельно.

| state | Значение |
| --- | --- |
| pending | Строка ещё не отправлялась |
| created | API подтвердил собственную новую PENDING_REVIEW карточку |
| duplicate | Сервер сообщил дубликат и его wordId |
| duplicate-in-file | Точный повтор нормализованной карточки внутри партии |
| rejected | Известный отказ 4xx, который не является дубликатом |
| in-flight / uncertain | Запрос начат, но создание не подтверждено однозначно |

На первом rejected/uncertain партия останавливается. Уже созданные слова остаются;
вся партия не является одной транзакцией. --resume для неизменённого JSON и того
же API/аккаунта пропускает created/duplicate/rejected и отправляет только pending.
Если нужно исправить rejected, подготовьте отдельную партию с нужными строками.

in-flight/uncertain блокирует автоматическое продолжение: проверьте слово и его
примеры в личном словаре/модерации, затем подготовьте отдельный список только
необходимых карточек. Сетевая ошибка/тайм-аут/5xx не вызывают слепого повторного POST.
Успешный ответ с чужим владельцем или статусом публикации также не подтверждает
импорт. Не редактируйте отчёт, чтобы скрыть неопределённый результат.

Рядом с отчётом на время работы создаётся .lock, блокирующий одновременные запуски.
После аварийного завершения сначала убедитесь, что другого процесса нет, проверьте
состояния строк и только затем уберите оставшийся lock-файл. Сам журнал сохраняется.
Код завершения 1 означает неполную партию/ошибку; числа состояний выведены в конце.

## Проверки и границы

`npm run test:import`: сборка и 15 тестов реального DTO, нормализации, валидации,
владения/PENDING_REVIEW, повторов, ошибок, refresh, отчёта, lock и сквозного CLI
через временный локальный HTTP API. Это не запуск на Render/Neon.
Excel создан Artifact Tool, оба листа визуально проверены. В экспортированном
XLSX проверены имена листов, пустые строки данных, отсутствие формул, валидация
и закрепление заголовков/двух первых столбцов. Сам Microsoft Excel не запускался.

Это CLI для подготовленного JSON, не кнопка загрузки Excel в веб-приложении.
Экспорт, автоматический XLSX/CSV-конвертер, подбор лексики/источников и импорт
реального пользовательского списка остаются отдельными действиями. Для самого
инструмента миграции и Deploy не нужны: он использует уже существующий API.
