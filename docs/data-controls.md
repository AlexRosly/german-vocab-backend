## Аккаунт

POST /api/v1/auth/account/archive принимает confirmation=ARCHIVE и method=password|google с соответствующим подтверждением. Только текущий пользователь из AuthGuard, произвольный userId запрещён. Для Google отдельный purpose=archive и одноразовый nonce, привязанный к пользователю; Google subject обязан совпадать с подключённым аккаунтом. Подтверждение пароля проверяется bcrypt, наличие тех же учётных данных повторно проверяется в Serializable-транзакции. Неверное подтверждение не архивирует аккаунт и не очищает cookie.

В транзакции users.archivedAt получает дату, все auth_sessions и Google challenges владельца удаляются. Словарь, личные материалы, роли, история, прогресс, общие карточки и данные других людей сохраняются. Cookie очищаются после commit. Authenticate/refresh и обычные password/Google login отклоняют архивированный профиль. Изменение archivedAt не публикуется в AuthUser.

POST /auth/restore с email/password и POST /auth/google/restore с отдельным purpose=restore явно возвращают доступ. Google restore не создаёт новый аккаунт. Старый пароль/подключённый Google подтверждают владельца; восстановление снимает archivedAt, выдаёт новые сессии, сохраняет ID и роль. Почтового сброса пароля этот выпуск не добавляет. Клиент использует существующий auth lock, generation/owner guards и межвкладочное уведомление; архивирование не повторяется автоматически после сетевой ошибки.

## Журнал общих изменений

Одна новая таблица word_audit_events и девять AFTER ROW триггеров: words, word_translations, word_examples, word_example_translations, word_relations, word_source_books, word_verb_forms, word_collocations, word_collocation_translations. Нет триггеров на private/account/study-таблицах. Snapshot исключает createdByUserId, revision и служебные timestamps; email, IP, токены и пароли не записываются. Пустые timestamp-only обновления не создают события. Связи отмечаются для обеих карточек; каскадное удаление дочерних переводов может отражаться корневой записью удаления родительского элемента, без восстановления несуществующей связи.

Автор из серверного AuthGuard хранится в AsyncLocalStorage и задаётся SET LOCAL только в той же Serializable-транзакции. Пул соединений не наследует автора следующего запроса. Для raw SQL/старого backend без контекста автор — система. При удалении пользователя FK SET NULL обезличивает журнал. Записи имеют transactionId для сопоставления нескольких изменений одной операции. Миграция не создаёт выдуманную прежнюю историю. Журнал сохраняется после удаления общей карточки, Word FK намеренно отсутствует.

GET /word-audit/config и GET /word-audit?page=1&search=... доступны только ADMIN; до 25 событий на страницу, no-store. UI в Настройках администратора: поиск, страницы, тип материала/действия, дата, тип автора, снимки до/после. Чужие email и внутренний actorId API не возвращает. API редактирования/очистки журнала нет.

## Резервирование

Docker pg_dump включает новую таблицу и триггеры автоматически. Прикладная JSON/SQL копия дополнительно сохраняет pg_get_functiondef и pg_get_triggerdef для функции журнала и девяти триггеров. При восстановлении функции/триггеры создаются после вставки сохранённых данных: история не дублируется, последующие изменения снова протоколируются. Копии содержат archivedAt и сохраняют состояние архивированных профилей.
