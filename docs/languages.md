# Языковые настройки и переводы слов

Backend хранит две независимые настройки пользователя: interfaceLanguage и
translationLanguage. На старте доступны ru, de, en, uk. Настройки уже предусмотрены
в Prisma User, поэтому изменений схемы и новой миграции не требуется.

| Метод | Путь после `/api/v1` | Назначение |
| --- | --- | --- |
| GET | /languages | Публичный каталог языков интерфейса и перевода |
| GET | /users/me/preferences | Только две настройки текущего пользователя |
| PATCH | /users/me/preferences | Изменить одну или обе настройки |
| GET | /words/:wordId/translations/:language | Получить перевод доступной карточки |
| PUT | /words/:wordId/translations/:language | Создать или заменить перевод с правами редактирования |

Все маршруты, кроме каталога /languages, требуют Bearer access token. Пользователь
определяется AuthGuard, а не из тела или query. GET /auth/me при следующем запросе
также возвращает актуальные языковые настройки из серверного контекста.

Пример PATCH /users/me/preferences:

```json
{ "interfaceLanguage": "de", "translationLanguage": "en" }
```

Изменение одного поля сохраняет другое. Язык интерфейса не определяет язык перевода.
Коды очищаются по краям и приводятся к нижнему регистру. Пустой PATCH, null,
неподдерживаемые коды, userId, role и прочие лишние поля отклоняются. Изменение
настроек не меняет словарь, WordProgress, StudySession или чужие настройки.

## Выбор перевода в ответах API

Карточки в words, личном словаре, ответах создания/изменения/добавления в словарь,
новых словах, повторениях, истории и прогрессе обучения дополнены полем:

```json
{
  "translation": "дерево",
  "selectedTranslation": { "language": "en", "text": "tree" }
}
```

selectedTranslation читается только из WordTranslation по translationLanguage
текущего пользователя. Старое поле translation в БД и JSON остаётся русским для
совместимости. Оно не заменяется английским текстом и не используется скрытым
резервом. Если нужной записи нет, selectedTranslation.text равен null, а language
содержит запрошенный язык. Это касается и отсутствующей русской записи:
значение legacy-поля не выдаётся за содержимое WordTranslation.

Frontend должен отображать selectedTranslation.text и отдельно показывать
отсутствие перевода. Настройки ещё не переводят интерфейс: языковые словари UI
и элементы выбора реализуются следующим этапом frontend.
Персональные GET-ответы words, study, preferences помечены Cache-Control: no-store.
Модерация продолжает возвращать все переводы и revision без выбора одного языка.

Язык представления не сохраняется в учебной сессии. Поэтому история и повтор
idempotent POST показывают текущий выбранный перевод, сохраняя тот же id сессии,
ответы, счётчики и даты. Смена языка не сбрасывает обучение и не создаёт новую сессию.

## Запись переводов

Пример PUT /words/:wordId/translations/en:

```json
{ "text": "tree" }
```

Текст очищается по краям и нормализуется в Unicode NFC; длина 1–1000 символов.
Язык определяется параметром пути. Лишние поля тела отклоняются.
Уникальность WordTranslation(wordId, language) сохраняется через upsert.
Повторный PUT заменяет текст одного языка, не удаляя остальные переводы.

Автор может менять только свои PENDING_REVIEW и REJECTED, администратор — любую
карточку. Чужая приватная карточка возвращает 404, обычная правка опубликованной — 403.
Правка перевода отклонённой карточки снова отправляет её в PENDING_REVIEW.
Сохранение выполняется в существующей транзакции доступа и обновляет родительский
Word; модерация получает новую revision и отклоняет старое решение.

Русский PUT использует существующий WordsService.update: синхронно меняет
Word.translation и WordTranslation(ru), сохраняя проверку точных дубликатов.
PUT других языков не меняет русское legacy-поле. GET перевода возвращает
`{ wordId, language, text }`, включая text=null, если у доступного слова перевода нет.
Изменение перевода меняет общую карточку, а не личную копию пользователя.

POST /words и поле translation в PATCH /words/:id сохраняют прежний русский
контракт независимо от выбранного языка. Для дополнительных языков используется
отдельный PUT. Создание карточки без начального русского перевода в этот этап
не входит; существующий интерфейс создания не получает новое значение старого поля.
Поле перевода WordExample пока одноязычное и не изменено.

## Расширение языков и проверки

Каталоги находятся в src/languages/language-options.ts. Добавление языка в нужный
каталог обновляет API-каталог и валидацию. Языки хранятся строками, не Prisma enum:
новая миграция не нужна. Для нового языка интерфейса frontend также потребует UI-словарь.

Из папки backend:

```powershell
npm run test:languages
node node_modules/typescript/bin/tsc --noEmit --incremental false
npm run build
```

Регрессионные команды: npm run test:auth, npm run test:words, npm run test:study,
npm run test:moderation. Новые тесты проверяют два независимых пользователя,
права редактирования, WordTranslation как источник, отсутствие подстановки русского,
сохранение legacy-поля, перевод учебных ответов, модерацию и idempotent повтор.
Тесты используют подмену Prisma, включая модели пользователей; они не заменяют
проверку сохранения настроек и переводов на настоящей тестовой ветке Neon.

На этом этапе схема, миграции и зависимости не меняются, Neon не затрагивается.
Следующий этап — адаптация frontend: вход, личный словарь, языковые настройки и
отображение выбранных переводов с сохранением существующих сценариев обучения.
