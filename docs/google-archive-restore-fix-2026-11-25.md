# Приёмка данных и исправление Google — 25.11.2026

На рабочем VPS/Netlify проверен существующий тестовый USER: архивирование завершает вход, обычный вход с верным паролем отклоняется с сообщением об архиве, явное восстановление паролем возвращает прежний профиль. Восстановлены все 104 карточки, одно трудное слово, 93 новых слова и 11 слов на повторение. Основной ADMIN не архивировался.

Под ADMIN журнал проверен реальным временным изменением общей заметки существующей отклонённой тестовой карточки `test`, затем исходная пустая заметка восстановлена. Обе операции записаны с категорией автора «Администратор» и снимками до/после. Другие поля и статус карточки не менялись; тестовая карточка не публиковалась.

## Найденный дефект

Google-восстановление при загрузке формы возвращает ошибку сервера: прежний CHECK `google_auth_challenges_purpose_check` из миграции 20261108120000 разрешает только login/null и link/owner. Предыдущая реализация расширила TypeScript purpose до archive/restore, но пропустила расширение этого CHECK. Синтетические проверки, создававшие схему только из Prisma, не воспроизводили ручное SQL-ограничение. Обычный Google-вход и привязка сохраняют прежнее поведение.

Новая отдельная миграция `20261125094000_extend_google_challenge_purposes` атомарно заменяет только этот CHECK. Старые применённые миграции не редактируются. Разрешённые пары: login или restore без userId; link или archive с обязательным userId. Иные purpose/сочетания отклоняются. Строки challenge, аккаунты, словари, прогресс и журнал не обновляются.

## Проверки

На изолированной PostgreSQL-схеме с настоящим Prisma выполнен исходный SQL Google-миграции 20261108120000. Настоящий GoogleAuthService.issue воспроизводит отказ archive и restore до исправления; после новой миграции успешно создаёт все четыре purpose. Пять неверных сочетаний purpose/userId отклоняются. Прежние строки сохранились. Внешняя Google-авторизация и production при этом не вызывались.

Свежая приватная копия рабочей Neon восстановлена вместе с реальными CHECK, функцией и триггерами. Исправление проверено на ней: все данные 28 таблиц сохранились без изменений; изменён только CHECK. Секреты, токены, дампы и персональные снимки в Git не включены. Дополнительно повторно проверен набор авторизации.

Исправляющая миграция применена 25.11.2026 с отдельного согласия владельца. Текущий backend уже умеет создавать archive/restore challenge; дополнительное изменение frontend или перезапуск VPS для одного CHECK не требуется. Полный Google archive/restore впоследствии принят владельцем в Firefox; подробности ниже. Парольная приёмка и проверка выдачи challenge сами по себе не объявляются полным входом через Google.

Миграция завершена 25.11.2026 в 21:06:37 Europe/Berlin (20:06:37 UTC). Сверены свежая восстановленная копия, единственная ожидающая миграция и контрольные суммы прежних миграций. После применения данные всех 27 прикладных таблиц и прежняя история миграций сохранены без изменений. Колонки, остальные CHECK и все определения функции/триггеров журнала сохранены. Изменён только согласованный CHECK; итог — 28 таблиц и 26 миграций. Срез: 4951 слово, 4981 пример, 8 пользователей, 7907 связей словаря, 454 записи прогресса, 42 тренировки и 1351 ответ.

Через публичный Netlify→VPS API проверены POST /api/v1/auth/google/challenge и POST /api/v1/auth/google/restore-challenge: оба HTTP 200, nonce создаётся, cookie Secure/HttpOnly/SameSite=Lax, Cache-Control=no-store. Значения nonce/cookie не публикуются. Тест создаёт только штатные краткоживущие challenge; Google identity не передавалась, реальные аккаунты не архивировались. Полный цикл с Google-аккаунтом отдельно принят владельцем в Firefox, как зафиксировано ниже.

## Полный Google-цикл принят владельцем в Firefox — 25.11.2026

Проверка проведена владельцем вручную в другом браузере, на тестовом USER с подключённым Google. Основной ADMIN во встроенном окне не архивировался. Владелец подтвердил: «Ошибок не было все 4 пункта прошли успешно».

1. Исходные количество карточек и прогресс проверены перед архивированием.
2. Архивирование подтверждено через подключённый Google, вход завершён.
3. Обычный Google-вход отклонён с сообщением об архивированном аккаунте.
4. Явное восстановление через тот же Google вернуло словарь и прогресс.

Таким образом, полный реальный Google-поток принят пользователем. Это подтверждение владельца, а не наблюдение агента через автоматизацию Firefox: среда остановила управление этим браузером из-за отсутствия поддержки проверки допустимых адресов. Пароли, коды и Google credentials агенту не передавались. Проверка архивирования/восстановления и ADMIN-журнала завершена; восстановление забытого пароля по email и публичный адрес для Impressum не входят в эту приёмку.
