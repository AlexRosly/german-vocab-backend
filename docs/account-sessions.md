# Управление активными входами

01.11.2026. Новые маршруты под `/api/v1/auth`, все требуют Bearer AuthGuard,
используют userId/sessionId из проверенного request.auth и возвращают no-store.
ADMIN не получает чужие входы и не может их отзывать.

| Метод | Путь | Ответ |
| --- | --- | --- |
| GET | /sessions | `{ sessions, hasMore }`, текущий вход первым |
| DELETE | /sessions/:id | 204, завершить один собственный вход |
| POST | /logout-all | 204, завершить все собственные входы |

GET читает один снимок RepeatableRead: текущий вход и до 100 других, у которых
refreshExpiresAt > now. Для остальных порядок createdAt DESC, id DESC.
Внутренний запрос ограничен take=101, лишняя запись задаёт hasMore.
Текущий вход включён даже если он старше всех остальных. Истёкший access может
быть обновлён refresh, поэтому он сам по себе не делает весь вход неактивным.

Поля строки только id, createdAt, updatedAt, refreshExpiresAt, current.
Ни userId/email, ни сырые токены, ни их хеши/credentials не выбираются для списка.
updatedAt — обновление записи доступа, а не подтверждение активности человека.
Имена устройств, IP, геолокация не собираются. Это управление входами, не журнал.

DELETE применяет оба условия id/userId; неверный формат id даёт 400. Для чужого,
отсутствующего и уже завершённого входа одинаковый 204 без раскрытия существования.
При удалении текущего входа очищается cookie с прежними Path/HttpOnly/SameSite/
Secure настройками. POST logout-all удаляет все auth_sessions данного userId,
включая истёкшие записи, и очищает cookie. Новые входы, созданные уже после этой
операции, требуют обычной авторизации и являются отдельными сессиями.

Удаление отзывает оба токена сразу: следующий AuthGuard/refresh не находит сессию.
Уже начатый refresh не может восстановить удалённую запись: существующий CAS
updateMany даёт count=0 и возвращает 401. Удаляется только состояние входа;
аккаунт, слова, настройки, история и учебный прогресс не меняются.
AuthOriginGuard и существующие лимиты Throttler защищают новые операции.

Prisma/схема/миграции/зависимости не менялись. Проверки: 28 auth-тестов и build,
в том числе 9 новых HTTP-сценариев с реальным AuthService и mock Prisma.
Проверены границы списка, приватная проекция, USER/ADMIN, истечение, повторный
отзыв, cookie, оба отозванных токена, чужой Origin и гонка refresh/отзыва.
Это не проверка SQL-конкурентности настоящего PostgreSQL. Реальные пользовательские
входы в Neon этим этапом не завершались. Выкладка: backend, затем frontend.
