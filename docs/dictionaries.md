# Общая библиотека и личные словари

Все маршруты `/api/v1/words`, включая примеры, требуют действующий Bearer access
token. Текущий пользователь определяется AuthGuard из серверной сессии.

| Метод | Путь после `/api/v1` | Назначение |
| --- | --- | --- |
| GET | /words?q=... | Библиотека: только PUBLISHED, поиск по слову и переводам |
| GET | /words/mine?q=... | Только личный словарь текущего пользователя |
| GET | /words/:id | Опубликованная или собственная карточка; ADMIN видит любую |
| POST | /words | Создать Word + русский WordTranslation + свой UserWord одной транзакцией |
| POST | /words/:id/dictionary | Добавить опубликованную или собственную карточку, без копии Word |
| DELETE | /words/:id/dictionary | Удалить только свой UserWord |
| DELETE | /words/:id | Совместимый маршрут: теперь тоже удаляет только свой UserWord |
| PATCH | /words/:id | Изменить свою неопубликованную карточку либо карточку как ADMIN |
| GET/POST | /words/:wordId/examples | Читать примеры / добавлять при наличии права редактирования |
| PATCH/DELETE | /words/:wordId/examples/:exampleId | Изменить/удалить пример при тех же правах |

`mine` объявлен до динамического `:id`. Списки возвращают массив карточек, вместе
с `translations`; аккаунты, чужие UserWord и прогресс в ответ не включаются.
Запрос `q` — строка до 100 символов. Неизвестные query-поля списков отклоняются.

Новые карточки всегда PENDING_REVIEW, автор берётся из сессии, включая создание
администратором. Поля publicationStatus, createdByUserId, userId и role не входят
в DTO создания/редактирования и отклоняются. Автоматической публикации нет.
Чужая неопубликованная карточка возвращает 404 по ID и через примеры.
Такую карточку нельзя добавить в словарь, даже зная её ID. Своя отклонённая
карточка остаётся доступной автору, если он сам не удалил её из своего словаря.

Обычный автор редактирует только PENDING_REVIEW или REJECTED. После правки
отклонённая карточка снова PENDING_REVIEW, включая правку её примеров.
Опубликованные общие слова и их примеры редактирует только ADMIN. Проверка права
и получение блокировки строки выполняются условным UPDATE в транзакции; решение
о публикации не может проскочить между проверкой права и изменением карточки.
Ни один маршрут этого этапа не удаляет общий Word. Прогресс, история и чужие
UserWord при удалении из словаря сохраняются; при повторном добавлении связь
восстанавливается без копирования слова. Повторное добавление/удаление безопасно.

## Переводы и дубликаты

Текущее поле DTO `translation` остаётся русским, как в исходном интерфейсе.
Создание и изменение синхронно записывают его в Word.translation и WordTranslation(ru).
Другие переводы не перезаписываются. Языковые настройки и выбранный перевод
теперь поддерживаются API: см. `docs/languages.md`. Поле translation сохраняет
русский контракт, а выбранный перевод возвращается как selectedTranslation.

При создании/правке ищется точный повтор доступной карточки: немецкое написание
без учёта регистра, тот же артикль, грамматическое число, перевод, множественная
форма и заметки. Текст очищается по краям и нормализуется в Unicode NFC.
Такой повтор возвращает 409 с wordId опубликованной или своей карточки. Клиент
может явно добавить её отдельным запросом. Автоматического объединения нет.
Различающиеся значения, формы и заметки остаются отдельными кандидатами на
модерацию. Чужие приватные совпадения не раскрываются и не используются повторно.
Разрешение неоднозначностей между разными авторами остаётся задачей модерации.

Записи выполняются с Serializable и ограниченным повтором конфликтов P2034/P2002.
Эта логика следует [рекомендациям Prisma 6](https://www.prisma.io/docs/orm/v6/prisma-client/queries/transactions).
Уникальный ключ UserWord(userId, wordId) сохраняет единственную личную связь.

## Проверки и состояние проекта

```powershell
npm run test:words
npm run test:auth
node node_modules/typescript/bin/tsc --project tsconfig.build.json --noEmit --incremental false
```

Тесты словарей запускают реальные сервисы и HTTP-контроллеры Nest с подменой Prisma.
Проверяются два пользователя, приватные карточки, опубликованные слова, авторство,
роль ADMIN, безопасное удаление, примеры, дубликаты и валидация. Изменение статуса
в старом тесте сохранения личной связи имитируется отдельно. API модерации теперь
реализовано и проверяется своими тестами: см. `docs/moderation.md`.
Тестовая подмена БД не подтверждает SQL, блокировки и изоляцию PostgreSQL — это
нужно проверить отдельно на тестовой ветке Neon после завершения адаптации API.

Новых зависимостей, изменений Prisma-схемы или миграций на этом этапе нет.
Миграция auth_sessions с предыдущего этапа всё ещё требует применения на тестовой
ветке перед реальными запросами с авторизацией. Основная база не затрагивается.
Study API теперь защищён и персонализирован, четыре прежние ошибки типов
устранены: см. `docs/study.md`. Проверки на настоящей тестовой БД и адаптация
frontend ещё необходимы перед публикацией.

Frontend пока не адаптирован: запросы к words без access token будут получать 401.
После адаптации библиотека загружается через /words, личный словарь — /words/mine,
добавление — /words/:id/dictionary. Старый DELETE теперь безопасно убирает личную
связь; создание больше не публикует слово в общей библиотеке.


Избранное и архив добавлены отдельным этапом: [dictionary-organization.md](dictionary-organization.md). Архив сохраняет UserWord и личные материалы; это отличается от DELETE dictionary.
