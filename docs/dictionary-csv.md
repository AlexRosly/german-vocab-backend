# Личный словарь: CSV v1, шаблон и будущий импорт

Релиз 18.11.2026 добавляет скачивание личного словаря и двух шаблонов в Настройках. Импорт CSV/Excel, предпросмотр дублей и экспорт истории тренировок остаются следующими этапами. Никаких записей в БД, миграций или изменений SRS в этом релизе нет.

## Доступ и границы

Авторизация обязательна на всех `/api/v1/dictionary-export/*`. `GET config` возвращает `{enabled:true,version:1}`; старый backend 404 скрывает панель. `GET csv` выгружает все доступные слова личного словаря, включая архив и избранное. ADMIN имеет те же ограничения: чужой словарь и чужие личные материалы не экспортируются. Неопубликованная чужая карточка исключается, даже если её прежняя личная привязка сохранилась. Не принимаются userId/role/query-параметры выбора чужих данных.

Чтение выполняется в RepeatableRead-транзакции с `SET TRANSACTION READ ONLY`, страницами по 200 слов. Вложенные личные заметки, переводы и книги фильтруются по текущему пользователю. Ответ не содержит пользователя, email, автора, auth-сессий, ревизий, паролей или токенов. Общие смысловые связи/сочетания и учебная история не входят в данный CSV; это перенос словарных материалов, не полный backup аккаунта.

Лимиты одного файла: 10000 слов, 10000 примеров, 25 MiB; при превышении возвращается 413, успешного обрезанного CSV нет. Тяжёлый экспорт — максимум 3 запроса в минуту на аккаунт через существующий Throttler; разные пользователи за Netlify не разделяют один IP-лимит. Перезапуск процесса обнуляет счётчик; распределённого лимитера пока нет. Шаблоны не обращаются к БД.

## Маршруты

| GET | Содержимое |
| --- | --- |
| `/dictionary-export/config` | Доступность и версия |
| `/dictionary-export/csv` | CSV личного словаря |
| `/dictionary-export/template?variant=blank` | Только заголовок простого шаблона, 0 карточек |
| `/dictionary-export/template?variant=example` | Отдельный пример: Haus, gehen, Guten Tag |

CSV-ответы: UTF-8 BOM, `text/csv; charset=utf-8`, attachment, `Cache-Control: private, no-store`, nosniff, `X-Wortkarten-Export-Version:1`, `X-Wortkarten-Word-Count`. Последние два заголовка необязательны клиенту при прямом CORS-доступе. Filename формирует сервер/клиент, не пользователь. Frontend не доверяет filename из ответа и не скачивает HTML/JSON как CSV. Размер проверяется во время чтения потока; отмена, размонтирование и смена аккаунта не создают файл старого пользователя.

## Формат

Разделитель `;` удобен для Excel RU/DE, строки CRLF, все поля заключены в двойные кавычки; внутренние кавычки удваиваются. Правила кавычек соответствуют [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180), разделитель выбран как явно описанный диалект. При несовпадающих региональных настройках Excel использовать «Из текста/CSV», UTF-8, точка с запятой.

Экспорт: одна строка на карточку, 58 фиксированных колонок. Простой шаблон содержит 20 колонок из того же словаря имён; отсутствие дополнительных колонок допустимо будущему импортёру.

| Группа | Колонки и смысл |
| --- | --- |
| Идентичность | `format_version=1`, `word_id` (сохранить при переносе), `german`, `word_type=noun/verb/other` |
| Грамматика | `article=der/die/das/none`, `grammatical_number=singular/plural/not_applicable`, `plural_form`, `level` (пусто сохраняет отсутствие уровня) |
| Источник | `source_book`, `lesson_number`; все общие привязки также в `source_books_json` с номерами уроков каждой книги |
| Переводы | `translation_<language>` для всех 11 языков каталога; переводы необязательны |
| Глагол | Первый вариант `praeteritum`, `participle_ii`, `auxiliary=haben/sein`, `reflexive=true/false`, `verb_usage`; остальные варианты в `extra_verb_forms_json` |
| Пример | Первый `example_id`, `example_german`, `example_translation_<language>`; остальные примеры с ID и всеми переводами в `extra_examples_json` |
| Личные материалы | `personal_note`, `personal_translation_<language>`, `personal_books_json`, `is_favorite`, `is_archived` |
| Общая заметка | `shared_note`; не смешивается с личной заметкой и не даёт права менять общую карточку импортом |

Общий и личный переводы выгружаются отдельно, без подстановки личного поверх общего. Существующий legacy-русский перевод сохраняется в явно русской колонке, если соответствующая строка translations отсутствует. Это не подстановка русского вместо выбранного языка интерфейса. `*_json` — JSON-массивы; новые строки простого шаблона не требуют их ручного заполнения. Существующие экспортированные значения оставить без изменений, чтобы не потерять дополнительные примеры/формы при будущем переносе.

## Защита формул и обратимость

Недостаточно только заключить ячейки в кавычки: [OWASP описывает CSV Injection](https://owasp.org/www-community/attacks/CSV_Injection). Наш генератор добавляет один TAB **внутрь кавычек** перед потенциальными формульными префиксами `= + - @`, полноширинными аналогами, ведущим апострофом и перед исходным TAB/CR/LF; также учитывается ведущий пробельный/управляющий префикс. Остальные строки сохраняются без преобразований. Кавычки/разделители внутри поля не могут создать отдельную ячейку.

Будущий импортёр экспорта v1 обязан снимать ровно один защитный TAB с поля, если `format_version=1`; исходный ведущий TAB был удвоен и восстановится. В простом пользовательском шаблоне без этого маркера не снимать произвольные символы молча. Значения никогда не исполняются как формулы. Нет универсальной гарантии для всех редакторов и повторного сохранения/открытия Excel: сохранять исходный скачанный файл и импортировать текстовые колонки как текст; XLSX с явными типами — следующий отдельный формат.

## Зафиксированные правила будущего импорта

1. Предпросмотр обязателен: новые, уже существующие, повторы внутри файла, неоднозначные, ошибки. Не создавать дубли до выбора пользователя.
2. Сохранённый word_id — только ссылка на доступную карточку, не разрешение перезаписать общие поля. Несовпадающие ID/слово/грамматика требуют уточнения. Произвольные ownerId/status/role игнорировать нельзя — запрещать серверной валидацией.
3. Без ID искать кандидатов по нормализованному немецкому слову, типу/артиклю/числу; NFC и пробелы нормализуются, умлауты/ß сохраняются. Книга, урок, личная заметка, новый пример не создают новое лексическое слово.
4. Не объединять разные значения автоматически: die Bank «банк» / «скамейка», der Leiter / die Leiter. Разные переводы без уверенного совпадения — ручной выбор. Текущая строгая ensureNoDuplicate сравнивает также заметки/множественное число; для массового импорта нужен отдельный этап поиска кандидатов, а не слепой обход старой проверки.
5. Повторить проверку доступности/дублей на сервере при записи. Пакет/строки должны иметь идемпотентность; повтор загрузки/ответа не сбрасывает прогресс и архив, не создаёт повторные примеры/привязки.
6. Общие новые карточки проходят обычные правила модерации. Личные переводы и заметки сохраняются только владельцу. Привязки книги/урока не дают права изменять общий источник или чужие личные материалы. Личные уроки пока отдельная незавершённая функция.
7. Проверить безопасный разбор CSV/XLSX, формулы как текст, ограничения строк/байтов/ячеек и отчёт ошибок. В этом релизе таких POST-endpoint и записи нет.

## Проверки

112 тестов словаря (в том числе 8 новых HTTP-тестов экспорта), 50 тестов авторизации; backend build. Frontend 176 клиентских тестов, lint/build, отдельная сборка без посторонних локальных правок. Настоящий экспорт владельца выполнен read-only: 3734 строки, 626 вариантов форм, 3751 пример, уникальные word_id; независимый Python csv-reader проверил 58 колонок, шаблон 0 и пример 3 строки. Приватный экспорт хранится вне Git. Браузерная проверка с одноразовым mock API подтвердила скачивание всех трёх файлов (независимо разобраны: 0/3/1 карточек), 503 → повтор, памятку и ширины 320/390 без горизонтальной прокрутки. Это не приёмка публичного VPS.

## Выпуск

Миграции и SMTP-настройка не нужны. Backend обновляет владелец под wortkarten: git pull --ff-only, npm ci --include=dev, npm run build, pm2 restart wortkarten-api --update-env. Netlify получает frontend из Git. Открыть Настройки → «Мои данные: CSV», скачать словарь и оба шаблона. До обновления backend панель скрыта по capability. Экспорт собственных тренировок и пользовательский импорт остаются открытыми пунктами roadmap.
