# Сочетания существительных с глаголами

Общие фразы связывают существующее существительное и существующий глагол с заполненными формами. Например: `mit dem Arbeitgeber sprechen` → карточка `sprechen` с `sprach`, `gesprochen`, `hat gesprochen`. Это отдельные данные от прежних смысловых связей слов.

## Доступ и редактирование

- Авторизация обязательна. USER видит сочетание, только когда ему доступны обе карточки; чужие неопубликованные карточки скрыты. ADMIN создаёт, редактирует и удаляет общие сочетания. Личный словарь и прогресс при этом не меняются.
- Пишется готовая немецкая фраза, а не автоматически подобранная пара слов. Подсказка по управлению и переводы необязательны. Поддерживаются все 11 языков каталога; отсутствие выбранного перевода возвращает `null`, без подстановки русского.
- Дубликат определяется по существительному, глаголу и нормализованной фразе (NFC, пробелы, регистр). Одновременно можно сохранить разные корректные сочетания с одним глаголом.
- PATCH и DELETE требуют `revision`. Устаревшая версия возвращает 409. Изменение выполняется в Serializable-транзакции с блокировками обеих карточек; их `updatedAt` обновляется, чтобы прежнее решение модерации не перезаписало проверенные данные. Статусы публикации сохраняются.
- Пока есть сочетания, нельзя убрать у существительного соответствующую категорию или удалить формы глагола: сначала администратор должен удалить/переназначить сочетания. Удаление карточки каскадно удаляет её сочетания.

## API

| Запрос | Результат |
| --- | --- |
| GET `/api/v1/collocations/config` | `{enabled, version:1}`; включается при наличии обеих новых таблиц |
| GET `/api/v1/words/:id/collocations?page=1` | `kind`, `items`, `total`, `page`, `pageSize:20`, `hasNext`; для глагола — обратный список |
| GET `/api/v1/words/:id/collocations/:collocationId` | Актуальная запись, если текущая карточка является одной из сторон |
| POST `/api/v1/words/:id/collocations` | ADMIN, `:id` — существительное; `verbWordId`, `german`, необязательные `grammarNote`, `translations` |
| PATCH `/api/v1/words/:id/collocations/:collocationId` | ADMIN, существительное; `revision` и изменяемые поля; пропущенные переводы сохраняются, `text:null` удаляет один язык |
| DELETE `/api/v1/words/:id/collocations/:collocationId` | ADMIN, существительное; JSON `{revision}`; подтверждение `{deleted:true}` |

Запись содержит минимальные данные обеих карточек, общие переводы и `selectedTranslation`. Все ответы без кеширования. Личные заметки и переводы других пользователей не выдаются.

## Начальная загрузка и развёртывание

Миграция `20261116120000_add_word_collocations` создаёт только `word_collocations` и `word_collocation_translations`. Перед применением к рабочей Neon требуется отдельное согласие владельца согласно AGENTS.md. На момент подготовки релиза миграция к production не применена.

`data/collocations-starter-20261116.json`: 10 проверенных фраз, 30 переводов RU/EN/UK, существующие опубликованные карточки. Импортёр не меняет строки words, формы, статусы, личные данные или прогресс. Проверяет ID, написание, категорию, дату инвентаризации, существующие связи; отличается от редактора тем, что предназначен только для начальной загрузки проверенного пакета. При отличающихся существующих данных останавливается, повторный запуск идентичного пакета — без изменений. После последующих правок карточек пакет нельзя слепо переиспользовать.

После отдельного согласия и свежей проверенной резервной копии:

1. Применить только ожидаемую миграцию через `prisma migrate deploy`; не использовать reset/db push.
2. Выполнить dry-run импортёра, сверив SHA256 файла и целевой hostname; затем тот же вызов с `--apply`.
3. Проверить 10 сочетаний/30 переводов и неизменность прежних таблиц, создать и проверить новую резервную копию из 22 таблиц.
4. Обновить backend на VPS обычным порядком (git pull, npm ci, npm run build, pm2 restart wortkarten-api --update-env). Frontend Netlify получает изменения из Git.
5. Проверить на опубликованном сайте существительное → сочетание → формы глагола, обратный переход, ADMIN-редактор и USER-просмотр. До обновления backend новая кнопка скрыта по capability; Netlify можно выпускать раньше backend.

CLI: `node --env-file=.env scripts/import-collocations.cjs --file data/collocations-starter-20261116.json --expect-host HOST --expect-sha256 REVIEWED_SHA256 [--apply]`. Без `--apply` транзакция только для чтения. Строку подключения и содержимое резервной копии не публиковать.

## Проверки релиза

- HTTP: реальные Nest-контроллеры/сервисы с подменённым хранилищем; права, приватность обеих сторон, обязательные формы, дубликаты, переводы, ревизии, блокировка смены категории, 20+1 записей, недоступная схема.
- Полный `test:words`, auth, study, moderation, languages, corrections, backup и сборка backend.
- Отдельная локальная PostgreSQL-копия: восстановлены 20 таблиц/3734 слова; применены SQL и импорт; старые данные совпали по хешам; повторный импорт — 0 вставок; FK/CHECK/UNIQUE и отказ при изменившихся данных проверены. Это не заменяет отложенную проверку восстановления внешнего Drive-архива.
- Интерфейс проверен в изолированной сборке с одноразовым mock API: German-only, RU/EN/UK, создание/изменение/удаление, конфликт 409 с сохранением черновика, переходы в обе стороны, вложенный редактор модерации, USER без кнопок записи, ширины 320/390 без горизонтальной прокрутки. Это не приёмка production-API.
