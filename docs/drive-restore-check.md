# Проверка восстановления из Google Drive

R02 принят 19.11.2026: реальная внешняя копия успешно восстановлена владельцем на VPS. Ниже — инструкция повторной проверки. Используется действующий remote `wortkarten-drive-own:WortkartenBackups-own/production` и обычные `.dump`/`.tar.gz` из скрипта пользователя. Настройка restic из старых документов к этому хранилищу не применяется.

## Запуск на VPS

Войти пользователем `wortkarten`, затем:

```bash
cd ~/apps/german-vocab-backend
git pull --ff-only
docker pull postgres:18.7
node scripts/check-drive-restore.cjs --check-config
node scripts/check-drive-restore.cjs --run
```

Нужны уже используемые Docker с образом postgres:18.7, rclone в ~/.local/bin/rclone и приватный ~/.config/rclone/rclone.conf, а также python3. Docker вызывается явно через локальный unix-сокет. root не нужен и отклоняется. Проверка конфигурации ничего не скачивает/не восстанавливает. Если образ отсутствует, сначала загрузить официальный `docker pull postgres:18.7`. Перед запуском оставить свободными хотя бы размер двух архивов плюс2ГиБ диска; контейнер ограничен768МиБ RAM и1 CPU. Скачанные копии и распакованный проект сохраняются приватно для осмотра; частые повторные запуски занимают дополнительный диск.

В конце получить JSON с `restored:true`, `cloudDownloadVerified:true`, `projectFilesRestored` и `counts`. Передать ассистенту только этот JSON. Отчёт находится в `~/backups/wortkarten-restore-checks/run-…/report.json`. Успешный реальный вывод на VPS получен 19.11.2026; R02 закрыт (отчёт приёмки ниже).

## Что делает --run

1. Выбирает последний `.dump` по имени. Требует архив проекта с точно таким же временем; неполную последнюю пару не подменяет более старой.
2. Скачивает оба объекта в новую приватную папку. `rclone check --one-way --download` сверяет каждый скачанный файл с Drive; дополнительно фиксируются SHA256. Cloud sync/delete/retention не выполняются.
3. Проверяет gzip до конца, безопасно распаковывает только обычные файлы/каталоги в новую папку project-restored, требует package.json и prisma/schema.prisma. Абсолютные/выходящие пути, ссылки, дубли файлов и чрезмерные размеры отвергаются. Восстановленные файлы0600/каталоги0700; исходные executable-биты в проверке не восстанавливаются. Код проекта и .env не запускаются.
4. Создаёт новый контейнер postgres:18.7 с уникальным именем/меткой, без сети и опубликованных портов. Данные лежат только в автоматически созданном Docker volume тестового контейнера. DATABASE_URL и конфигурация приложения не читаются/не передаются.
5. Копирует dump, выполняет pg_restore через локальный Unix socket внутри контейнера: отдельная wortkarten_restore, single-transaction, exit-on-error, clean/if-exists, no-owner/no-acl. Поэтому проверяется восстановление схемы/данных, а не исходные роли владельцев/ACL Neon.
6. Проверяет наличие основных таблиц, непустые users/words, валидированные ограничения и завершённость миграций; возвращает счётчики слов, примеров, пользователей, словаря, сессий, ответов, прогресса и миграций. Это не сравнение хешей каждой строки с меняющейся production БД.
7. Удаляет только свой контейнер/его временные volumes после проверки уникальной метки. При сбое пытается очистить тот же контейнер; при несовпадении метки ничего не удаляет. Скачанные файлы/отчёт не удаляются. Рабочие PM2, Neon, расписание и Drive остаются прежними.

Ошибка выводит этап и приватную папку; подробности subprocess лежат в приватном *.error.log. Не выполняется автоматический откат/восстановление поверх production. Подход соответствует первичным инструкциям [pg_restore](https://www.postgresql.org/docs/18/app-pgrestore.html), [официального образа PostgreSQL](https://hub.docker.com/_/postgres) и [rclone check](https://rclone.org/commands/rclone_check/).

## Исправление pg_attver — 19.11.2026

Первый реальный прогон на VPS скачал/сверил пару Drive-архивов и распаковал проект, но pg_restore завершился `unrecognized parameter "pg_attver"`. Это не подтверждение повреждения dump. В PostgreSQL 18.7 от12.11.2026 добавлен новый механизм версионирования составных типов. Старый pg_dump может включить внутренние атрибуты нового источника; сервер без этого изменения их не распознаёт. [Первичный commit с описанием совместимости](https://www.postgresql.org/message-id/E1xQQFr-000000003OT-3txh%40gemulon.postgresql.org), [release18.7](https://www.postgresql.org/docs/18/release-18-7.html).

Для тестового восстановления используется явно postgres:18.7 вместо потенциально старого локального тега :18. После запуска контейнера проверяется server_version_num>=180007 и<190000, до копирования/восстановления dump; версия и образ сохраняются в успешном отчёте. pg_restore остаётся single-transaction/exit-on-error, SQL дампа не редактируется, ошибки не игнорируются. Чужие контейнеры и рабочие БД не обновляются.

После git pull выполнить docker pull postgres:18.7 и повторить --run. Пересборка Nest/перезапуск PM2 для этого исправления не нужны. Повторное скачивание берёт актуальную проверенную пару, предыдущий run-3upSIP сохраняется. После этого исправления владелец получил успешный отчёт нового прогона; см. приёмку ниже.
