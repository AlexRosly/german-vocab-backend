# Проверка восстановления из Google Drive

Это следующий шаг R02 после уже принятого ночного резервирования и мониторинга. Используется действующий remote `wortkarten-drive-own:WortkartenBackups-own/production` и обычные `.dump`/`.tar.gz` из скрипта пользователя. Настройка restic из старых документов к этому хранилищу не применяется.

## Запуск на VPS

Войти пользователем `wortkarten`, затем:

```bash
cd ~/apps/german-vocab-backend
git pull --ff-only
node scripts/check-drive-restore.cjs --check-config
node scripts/check-drive-restore.cjs --run
```

Нужны уже используемые Docker с образом postgres:18, rclone в ~/.local/bin/rclone и приватный ~/.config/rclone/rclone.conf, а также python3. Docker вызывается явно через локальный unix-сокет. root не нужен и отклоняется. Проверка конфигурации ничего не скачивает/не восстанавливает. Если образ отсутствует, сначала загрузить официальный `docker pull postgres:18`. Перед запуском оставить свободными хотя бы размер двух архивов плюс2ГиБ диска; контейнер ограничен768МиБ RAM и1 CPU. Скачанные копии и распакованный проект сохраняются приватно для осмотра; частые повторные запуски занимают дополнительный диск.

В конце получить JSON с `restored:true`, `cloudDownloadVerified:true`, `projectFilesRestored` и `counts`. Передать ассистенту только этот JSON. Отчёт находится в `~/backups/wortkarten-restore-checks/run-…/report.json`. До реального успешного вывода на VPS R02 остаётся открытым.

## Что делает --run

1. Выбирает последний `.dump` по имени. Требует архив проекта с точно таким же временем; неполную последнюю пару не подменяет более старой.
2. Скачивает оба объекта в новую приватную папку. `rclone check --one-way --download` сверяет каждый скачанный файл с Drive; дополнительно фиксируются SHA256. Cloud sync/delete/retention не выполняются.
3. Проверяет gzip до конца, безопасно распаковывает только обычные файлы/каталоги в новую папку project-restored, требует package.json и prisma/schema.prisma. Абсолютные/выходящие пути, ссылки, дубли файлов и чрезмерные размеры отвергаются. Восстановленные файлы0600/каталоги0700; исходные executable-биты в проверке не восстанавливаются. Код проекта и .env не запускаются.
4. Создаёт новый контейнер postgres:18 с уникальным именем/меткой, без сети и опубликованных портов. Данные лежат только в автоматически созданном Docker volume тестового контейнера. DATABASE_URL и конфигурация приложения не читаются/не передаются.
5. Копирует dump, выполняет pg_restore через локальный Unix socket внутри контейнера: отдельная wortkarten_restore, single-transaction, exit-on-error, clean/if-exists, no-owner/no-acl. Поэтому проверяется восстановление схемы/данных, а не исходные роли владельцев/ACL Neon.
6. Проверяет наличие основных таблиц, непустые users/words, валидированные ограничения и завершённость миграций; возвращает счётчики слов, примеров, пользователей, словаря, сессий, ответов, прогресса и миграций. Это не сравнение хешей каждой строки с меняющейся production БД.
7. Удаляет только свой контейнер/его временные volumes после проверки уникальной метки. При сбое пытается очистить тот же контейнер; при несовпадении метки ничего не удаляет. Скачанные файлы/отчёт не удаляются. Рабочие PM2, Neon, расписание и Drive остаются прежними.

Ошибка выводит этап и приватную папку; подробности subprocess лежат в приватном *.error.log. Не выполняется автоматический откат/восстановление поверх production. Подход соответствует первичным инструкциям [pg_restore](https://www.postgresql.org/docs/18/app-pgrestore.html), [официального образа PostgreSQL](https://hub.docker.com/_/postgres) и [rclone check](https://rclone.org/commands/rclone_check/).

## Проверки реализации

`npm run test:restore` —9сценариев с подменой rclone/Docker: безопасные имена/последняя пара, check-config без переноса, success path, порча копирования/отсутствующая пара, сбой pg_restore, чужая метка без удаления, отсутствие production env/URL/портов/mounts в командах. Python действительно распаковывает синтетический tar.gz и отвергает traversal/ссылки без выполнения файлов. Реальные Drive/Docker/VPS в этих тестах не использовались; это подготовка инструмента, не закрытие R02.
