# Предложения исправлений — 09.11.2026

## Работа пользователя и администратора

В опубликованной карточке личного словаря или библиотеки есть «Предложить исправление». Категории: слово/грамматика, перевод, пример, общие связи, другое. Обязательное описание — 10–2000 символов; предлагаемый вариант необязателен, до 2000 символов.

Предложение сохраняется отдельно и **не меняет общую карточку**. На одну карточку у одного пользователя может быть только одно открытое обращение. После рассмотрения можно отправить новое. В разделе «Исправления» пользователь видит только свои предложения и комментарии к решениям.

Администратор в этом разделе видит очередь всех пользователей (по умолчанию открытые), а также может переключиться на свои обращения. Статусы: OPEN / «Ожидает рассмотрения», RESOLVED / «Исправлено», REJECTED / «Отклонено». Список — по 30 записей, с пагинацией и фильтром статуса.

В обращении есть снимок **общей** карточки на момент отправки: слово, грамматическая форма, источник/урок, общая заметка, переводы, примеры и опубликованные связанные слова. Личные заметки и личные переводы не включаются. Также показывается текущая общая карточка, если она доступна; при изменении содержания выводится предупреждение. История автора не раскрывает актуальное содержимое снятой с публикации карточки.

«Открыть карточку в модерации» переводит администратора к существующим средствам редактирования переводов/связей/источника. Добавлена кнопка «Изменить слово» для перехода к общей форме редактирования. Примеры по-прежнему редактируются существующим редактором карточки в словаре. Применение предложения не автоматическое: сначала внести нужные правки, затем вернуться в «Исправления» и отметить результат с комментарием пользователю (3–1000 символов).

При решении передаётся revision обращения. После другого решения устаревшая версия получает 409; повтор не переписывает комментарий. После неопределённой ошибки решения интерфейс требует загрузить актуальную версию. Администратор может отклонить неверное замечание, не меняя карточку. Закрытые обращения через этот интерфейс не переоткрываются.

## API

Все маршруты требуют обычной сессии. Административные дополнительно защищены AdminGuard; сервис тоже проверяет роль.

| Маршрут | Назначение |
| --- | --- |
| GET /api/v1/corrections/config | `{enabled}`; таблица ещё не создана → false |
| POST /api/v1/words/:wordId/corrections | category, description, необязательный suggestion; только PUBLISHED |
| GET /api/v1/corrections/mine?status=OPEN&page=0 | Только обращения вызывающего пользователя |
| GET /api/v1/corrections/mine/:id | Собственное обращение, исходный снимок и доступная текущая карточка |
| GET /api/v1/moderation/corrections?status=OPEN&page=0 | Административная очередь |
| GET /api/v1/moderation/corrections/:id | Подробности для администратора |
| PATCH /api/v1/moderation/corrections/:id | status=RESOLVED/REJECTED, expectedRevision, comment |

Присланные userId/reporterId/reviewerId/status/snapshot при создании и другие лишние поля отвергаются. Неавторизованный запрос → 401, обычный пользователь на административном маршруте → 403, чужое личное обращение → 404. API не отдаёт email, account/password/session данные, reporterId или reviewerId. Авторство и рассмотревший администратор хранятся в БД для внутренней целостности.

## Миграция и выпуск на VPS / Netlify

Миграция: `prisma/migrations/20261109120000_add_word_corrections/migration.sql`. Это 15-я миграция проекта. Она в одной транзакции создаёт только два enum и таблицу word_corrections с индексами/FK/CHECK. Прежние 17 таблиц и их данные не изменяются. Индекс «одно OPEN на пользователя/карточку» частичный; его нет в декларативной Prisma-схеме, поэтому backup-скрипт восстанавливает его отдельно.

Перед любым применением к основной Neon нужно отдельное согласие владельца по AGENTS.md. Команды ниже выполняются в фактическом каталоге backend на VPS. Миграция не добавлена в build/start. Сохраняется тот же DATABASE_URL; для этой функции не нужно создавать/переключать ветку БД.

1. **До обновления кода** сохранить актуальную полную приватную копию старой схемы скриптом текущей установленной версии: `node --env-file=.env scripts/backup-database.cjs --expect-host CURRENT_NEON_HOST --directory /private/backups/before-corrections`. Каталог должен быть новым и вне Git. Проверить восстановление отдельно; сохранять копию вне VPS.
2. `git pull --ff-only origin main`, затем `npm ci --include=dev` и `npm run build`.
3. `npx prisma migrate status`. Ожидается ровно одна новая миграция add_word_corrections. При других pending/failed сначала выяснить расхождение.
4. **Только после отдельного согласия:** `npx prisma migrate deploy`. Если миграция уже применена из локального операторского окружения, повторное deploy просто проверит актуальность; повторный SQL вручную не исполнять.
5. Через `pm2 list` проверить фактическое имя Wortkarten API и перезапустить **только его** с `--update-env`, затем проверить health. Другие приложения не перезапускать. Если используется имя из инструкции проекта: `pm2 restart wortkarten-api --update-env`.
6. Netlify получает frontend из main. До обновления backend или создания таблицы новый раздел скрыт (старый API 404 / enabled:false), чтобы не ломать существующую работу. После готовности API обновить страницу/войти заново и проверить появление «Исправления».
7. Создать пробное обращение обычным пользователем; ADMIN должен видеть его, оставить решение и комментарий; автор должен видеть ответ. Убедиться, что общая карточка сама не изменилась и прогресс словаря сохранился.
8. Сделать свежую полную копию уже **18 таблиц** обновлённым скриптом. Не применять старый backup-скрипт на новой схеме. При откате кода данные обращений не удалять.

Для текущей рабочей БД перед подготовкой сохранена копия вне Git `2026-11-09-before-corrections` в WortkartenBackups. Она содержит auth-хеши: не публиковать. Старые 17 таблиц проверены восстановлением в PGlite; там же применена новая миграция и выполнено полное восстановление 18-табличной копии с проверкой хешей, FK, CHECK, уникального OPEN и защиты revision.
