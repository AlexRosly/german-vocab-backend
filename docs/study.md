# Персональное обучение

Все маршруты `/api/v1/study` защищены AuthGuard. userId поступает только из
проверенной серверной сессии через @CurrentUser; роли ADMIN не дают доступа к
чужой истории или возможности изучать слова вне своего личного словаря.

| Метод | Путь после `/api/v1` | Результат |
| --- | --- | --- |
| POST | /study/sessions | Создать свою учебную сессию и обновить свой прогресс |
| GET | /study/sessions | История только текущего пользователя (совместимый старый массив) |
| GET | /study/history | Ограниченные страницы итогов тренировок |
| GET | /study/history/:id | Детали одной своей тренировки |
| GET | /study/progress | Персональная статистика и текущий активный прогресс |
| GET | /study/due | Слова своего словаря с наступившей датой повторения |
| GET | /study/new | Слова своего словаря, ещё не изучавшиеся этим пользователем |

Формы ответов прежние. Ответы помечены Cache-Control: no-store. Включённые
карточки также содержат translations и selectedTranslation из текущей языковой
настройки пользователя: см. `docs/languages.md`.

## Сохранение сессии

```json
{
  "totalWords": 2,
  "words": [
    { "wordId": "id-1", "answer": "KNOWN" },
    { "wordId": "id-2", "answer": "NEEDS_REVIEW" }
  ]
}
```

DTO теперь классы с вложенной валидацией: от 1 до 500 разных слов, totalWords
точно совпадает с числом ответов, каждый wordId непустой и без пробелов,
answer только KNOWN или NEEDS_REVIEW. Неизвестные поля, включая userId,
role, knownCount и вложенные поля авторизации, отклоняются.

Перед любыми записями проверяются все слова: каждое должно иметь UserWord
текущего пользователя и быть опубликованным либо созданным этим пользователем.
Автор может изучать свои PENDING_REVIEW и REJECTED. Чужое приватное слово
не проходит проверку даже при ошибочно существующей личной связи. Нет обхода
для администратора. Если хоть одно слово недоступно, сессия целиком отклоняется.

Сессия и прогресс записываются одной транзакцией Serializable. WordProgress
ищется и обновляется по userId_wordId. Конфликты P2034/P2002 повторяются не
более трёх попыток; затем возвращается 409. Это соответствует подходу из
[документации Prisma 6](https://www.prisma.io/docs/orm/v6/prisma-client/queries/transactions).

## Интервальное повторение

Алгоритм сохранён: KNOWN увеличивает consecutiveKnown и назначает 1, 3, 7, 14,
30 дней, дальше остаётся 30. NEEDS_REVIEW сбрасывает серию в 0 и назначает 1 день.
Дата вычисляется от текущего времени ответа. Ранний ответ KNOWN тоже увеличивает
серию, как в исходной реализации. Счётчики knownCount/needsReviewCount персональные.

## Защита от повторного сохранения

Frontend может передать `Idempotency-Key`, например один crypto.randomUUID()
на завершённую сессию. Допустимы 8–128 символов ASCII: буквы, цифры, . _ : -.
Заголовок добавлен в allowedHeaders CORS. Он необязателен для совместимости.

Один и тот же ключ и те же ответы возвращают прежнюю сессию, не изменяя
счётчики и даты. Порядок ответов при сравнении не важен. Повтор с изменёнными
ответами получает 409. Один ключ у разных пользователей означает разные сессии.
Ключ задаёт серверный id сессии через SHA-256 пары userId/ключ; существующий
первичный ключ StudySession обеспечивает уникальность без изменения схемы.
Повтор после удаления личной связи разрешён как чтение уже сохранённой сессии;
новая сессия после удаления связи отклоняется. Без ключа каждый POST считается
отдельной намеренной сессией. Ключ хранится логически в id на весь срок хранения сессии.

## Словарь, статистика и история

Новые слова: UserWord текущего пользователя и отсутствие WordProgress только
этого пользователя. Чужой прогресс не мешает слову быть новым для вас.
Повторения: только ваш WordProgress, активная личная связь, допустимая видимость
слова и nextReviewAt <= now. Порядок nextReviewAt/updatedAt сохранён.

Удаление UserWord не удаляет прогресс и историю. Удалённое слово исчезает из
новых слов, повторений и активной статистики. Повторное добавление продолжает
сохранённый прогресс; оно не делает ранее изученное слово новым.

totalSessions включает всю вашу историю, включая удалённые из словаря слова.
totalWordsInDictionary, wordsWithProgress, knownAnswers, needsReviewAnswers,
studiedToday, dueCount и список words относятся к текущему доступному словарю.
Статистика читается в одной транзакции RepeatableRead для согласованности чисел.
«Сегодня» определяется по сохранённому timeZone пользователя (по умолчанию UTC);
дневная цель и контракт описаны в [study-preferences.md](study-preferences.md).

История фильтруется по владельцу сессии. Детали слов доступны после удаления
UserWord, если слово всё ещё опубликовано или создано вами. Чужая карточка,
ставшая приватной, из вложенного words скрывается. Исходные totalWords и счётчики
сессии сохраняются, поэтому число видимых деталей может быть меньше totalWords.
Такая же фильтрация применяется к ответу повторного idempotent POST.

## Проверки и ограничения этапа

Из папки backend:

```powershell
npm run test:study
npm run test:words
npm run test:auth
node node_modules/typescript/bin/tsc --noEmit --incremental false
npm run build
```

Тесты проверяют реальные сервисы и HTTP через полный AppModule с подменой Prisma.
Проверяются два пользователя, все интервалы, сброс серии, приватные карточки,
удаление/возврат слов, история, статистика, валидация, повторные запросы и откат.
Они не заменяют проверку SQL и конкурентных транзакций на настоящем PostgreSQL.

Prisma-схема, миграции и зависимости на этом этапе не меняются. Существующая
миграция auth_sessions должна быть отдельно проверена и применена на тестовой
ветке перед реальными запросами с авторизацией. База Neon на этом этапе не трогается.

Frontend использует Bearer access token и сохраняет Idempotency-Key при повторе
завершённой сессии. Языки UI и карточек реализованы независимо. Отдельный экран
истории использует новые маршруты: см. [study-history.md](study-history.md).
Модерация описана в [moderation.md](moderation.md).
