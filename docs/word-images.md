# Изображения карточек — 26.11.2026

Одна необязательная иллюстрация на слово. Код готов. Миграция `20261126120000_add_word_images` применена к рабочей Neon 26.11.2026 с отдельного согласия владельца; прежние данные сохранены. Обновление, включение на VPS и рабочая приёмка ещё впереди. [Отчёт применения](word-images-migration-2026-11-26.md).

## Пользовательское поведение

- В словаре и обучении по уроку есть миниатюра 128×96 с увеличением по нажатию. Редактор открывается отдельно, не растягивает каждую карточку формой. В тренировке изображение появляется только после раскрытия/проверки ответа; редактирование там недоступно.
- ADMIN может загрузить, заменить или убрать изображение любой карточки. USER — только своей неопубликованной (`PENDING_REVIEW`/`REJECTED`); изменение возвращает отклонённую карточку на проверку. Изображение общее и публикуется вместе с карточкой. У чужой неопубликованной карточки недоступны и метаданные, и файл.
- В модерации изображение видно перед решением о публикации. Прежние картинки не сохраняются в снимке старого учебного ответа: просматривается текущее изображение слова.
- Ошибка не сбрасывает выбранный файл. Устаревшая revision даёт 409: нужно загрузить и просмотреть актуальную версию перед повторной записью. Новое изображение не создаёт ответов тренировки и не меняет SRS.

## Формат, хранение и границы

JPEG/PNG/WebP до **4 MiB**, до 24 миллионов пикселей; неподдерживаемые форматы, повреждённые данные, подмена MIME и поддерживаемая библиотекой многостраничная анимация отклоняются. Sharp 0.35.5 проверяет содержимое, учитывает ориентацию, удаляет метаданные исходного фото и перекодирует в WebP до 720×720 и 96 KiB. При необходимости снижает размер/качество; исходный файл и имя не сохраняются. Одновременно кодируется одно изображение; повторить можно после завершения текущего. Загрузка ограничена восемью запросами в минуту на аккаунт.

В `word_images` — только связь с Word, ключ файла, SHA-256, размер, габариты и revision. Файлы — **`<cwd backend>/storage/word-images`**, для текущего VPS `/home/wortkarten/apps/german-vocab-backend/storage/word-images`. Каталог не публикуется Nginx, файлы читаются через авторизованный API; существование UUID не даёт доступ. В JSON нет пути к хранилищу. Браузер получает Blob через apiClient и освобождает временные object URL при смене карточки/аккаунта. Метаданные и бинарные ответы имеют `private, no-store`.

Файлы неизменяемые, с новыми UUID при замене. Старые и незавершённые версии остаются для согласованного восстановления копий; автоматического GC в этом выпуске нет. Ограничение всего каталога — 384 MiB / 10000 файлов, включая неиспользуемые версии. При заполнении новая запись отклоняется без замены текущей картинки. Не чистить каталог вслепую: файл может требоваться текущей БД или сохраняемой резервной копии. Для масштабирования за этот лимит потребуется отдельное решение по хранилищу/ротации.

Изображения не входят в CSV/XLSX словаря. Они сохраняются через пару «дамп БД + архив проекта»; это явно описано на `/privacy`. Изменения метаданных входят в ADMIN-журнал (`word_images`), без бинарных данных. Наличие файлов не меняет личные переводы, заметки, прогресс или книги.

## API и совместимость

| Метод и путь | Назначение |
| --- | --- |
| GET `/word-images/config` | `{enabled, version:1}`; выключено без флага или таблицы. |
| GET `/words/:wordId/image` | `{image:null}` либо `{image:{revision,width,height,bytes}}`. |
| GET `/words/:wordId/image/content?revision=UUID` | Текущий WebP после проверки доступа; устаревшая версия — 404. |
| PUT `/words/:wordId/image` | Multipart: `file` и `revision` (пустая строка означает отсутствие изображения). Новая revision, доступ и MIME проверяются сервером. |
| DELETE `/words/:wordId/image` | JSON `{revision}`; убрать текущую связь с картинки, оставив файл для восстановления. |

`WORD_IMAGES_ENABLED=false` по умолчанию. Пока VPS не обновлён или флаг выключен, новый frontend скрывает функцию. Старые функции не зависят от новой таблицы. Файлы не включаются в массовые ответы словаря и загружаются только возле видимой карточки. Старый frontend не знает новый тип ADMIN-журнала, поэтому включать изображения следует **после** публикации нового frontend.

## Миграция и проверка

Миграция добавляет одну таблицу с ограничениями размера/габаритов, уникальными ключом/revision, FK к Word и десятый триггер общего журнала. Старые таблицы/строки не переписываются. Перед запросом согласия свежая приватная копия Neon восстановлена отдельно: все данные прежних 28 таблиц сохранены после миграции, новая таблица пуста; ограничение/FK и работа аудита проверены на восстановлении, тестовая запись отменена. Миграция production применена 26.11.2026 после отдельного согласия: 27 прежних прикладных таблиц и прежняя история миграций сохранены; добавлена одна успешная миграция (всего 27), таблица word_images пуста, триггер аудита готов.

Проверки: backend — 174 теста словаря, включая 9 HTTP-сценариев изображений, и тесты модерации; backup/restore — 20 проверок; frontend — 268 тестов, lint и production-сборка. Точные результаты выпуска см. в коммите. В браузере использован настоящий Nest-обработчик изображений за синтетическими авторизацией/словарём, без Neon: PNG→WebP, увеличение, JPEG-замена, сохранение после перезагрузки, отклонение неверного файла, отсутствие подсказки до раскрытия ответа и режим просмотра без редактора в тренировке. Ширины 320/390 без переполнения. Это не подтверждение выпуска на VPS или реального iPhone.

2. Под пользователем `wortkarten` в `~/apps/german-vocab-backend`: обычный `git pull --ff-only`, `npm ci`, `npm run build`, `pm2 restart wortkarten-api`. Node ≥20.9, рекомендован уже настроенный Node 22. Prisma остаётся 6.19.3. Проверить health; флаг пока не включать. Не менять окружение других приложений VPS.
3. Дождаться нового Netlify frontend. В API-виртуальном хосте Nginx проверить лимит запроса не ниже 6m (multipart+заголовки); не уменьшать более высокий лимит, нужный импорту Excel. Шаблоны Hestia обновлены, но активный конфиг автоматически не меняется. Применять изменения только для API-домена и после проверки `nginx -t`.
4. Проверить `cwd` PM2 и что `storage/word-images` входит в реальный архив проекта существующего `~/scripts/backup-german-vocab.sh`. Не использовать `git archive` или исключение всех gitignored-файлов для этого каталога; не хранить его в `dist`/`node_modules`. Текст `.env`, конфиги rclone и ключи в чат не отправлять.
5. Только затем добавить **`WORD_IMAGES_ENABLED=true`** в приватный `.env` через редактор и перезапустить `pm2 restart wortkarten-api --update-env`. PM2 ecosystem уже загружает `.env` через Node `--env-file`; полный `.env` не пересоздавать. Убедиться в доступности функции на сайте и загрузить одну разрешённую тестовую иллюстрацию.
6. Выполнить обычный backup через существующий `wortkarten-script-backup.service`, затем под `wortkarten` запустить `node scripts/check-drive-restore.cjs --run`. После появления хотя бы одной картинки успех должен содержать `imageFilesVerified >= 1`. Нулевой счётчик до первой загрузки не доказывает резервирование файлов. Проверяются SHA-256 каждого изображения из **восстановленной** БД и его наличие в парном восстановленном архиве. Никакое содержимое архива не исполняется. При отсутствии файлов исправить архивирование и повторить проверку; этап не закрывать только по зелёному backup-уведомлению.
7. Приёмка: под ADMIN — загрузка/замена и запись в журнале; под USER — просмотр опубликованного, запрет изменения чужого/опубликованного и доступ к своей ожидающей модерации карточке; на телефоне — миниатюра/увеличение и тренировка после раскрытия ответа. При откате выключить флаг; таблицу и файлы оставить для восстановления.
