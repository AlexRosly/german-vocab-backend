# CSV: загрузка и предпросмотр, 18.11.2026

Завершён отдельный read-only этап R09. В Настройках под CSV-экспортом можно выбрать файл по нашему шаблону, проверить его по общему каталогу и своим неопубликованным карточкам, отфильтровать результаты и увидеть кандидатов. **Записи в БД, кнопки сохранения, сопоставления произвольных колонок и XLSX в этом релизе нет.** Полный пользовательский импорт ещё не завершён. Приёмка скачивания CSV на публичном сайте подтверждена владельцем до этого этапа.

## API

- Авторизованный `GET /api/v1/dictionary-import/config` возвращает `enabled:true,version:1,readOnly:true,formats:["csv"],maxBytes:26214400,maxRows:10000`. Старый API 404 скрывает блок предпросмотра; уже работающий экспорт доступен отдельно.
- `POST /api/v1/dictionary-import/preview`: multipart, ровно один файл в поле `file`, имя с окончанием `.csv`; никаких дополнительных полей или query. HTTP 200, `Cache-Control: private, no-store`. Файл не сохраняется на диске и не записывается в логи. Срок хранения — память текущего запроса и открытой страницы; при смене аккаунта результаты сбрасываются.
- `version:1,readOnly:true,total,counts:{new,existing,duplicate,choice,error},rows`. Номер `row` — номер записи данных, начиная с 1, не физической строки CSV: внутри кавычек могут быть переносы.
- Не более 3 предпросмотров в минуту на аккаунт. Ошибки 400/413/429, временные ошибки можно повторить вручную. Автоматических записей или повторных мутаций нет.

## Формат и границы

Поддержаны простой шаблон и полный [экспорт v1](dictionary-csv.md): UTF-8/BOM, `;`, кавычки, `""`, многострочные поля. Нужны `german,word_type,article,grammatical_number`; остальные колонки необязательны. Неизвестные и дублирующиеся названия колонок запрещены: это также исключает передачу userId, роли или статуса публикации. Формулы не вычисляются. Один защитный TAB снимается только с помеченного экспорта `format_version=1`; у обычного шаблона произвольный TAB/апостроф не удаляется.

Лимиты: 25 MiB файла, 10000 записей, 256 KiB одной CSV-записи, 64 Ki символов одной ячейки; примеры/переводы/формы проходят текущие DTO-ограничения карточки. Проверяются дополнительные JSON-массивы, личные поля, книги/уроки, boolean true/false. Полный текущий словарь укладывается в эти лимиты. Файл с нарушенным форматом или превышением общего лимита отклоняется целиком, без успешного усечения. Ошибки отдельных полей возвращаются по записям.

Парсер — закреплённый csv-parse 7.0.3. [Документация Sync API](https://csv.js.org/parse/api/sync/), [лимит записи](https://csv.js.org/parse/options/max_record_size/). Разбор не использует eval и не исполняет содержимое ячеек.

Если публичный reverse proxy возвращает 413 до обращения к приложению, его лимит тела запроса меньше прикладного: проверьте настройки Nginx/Hestia/Netlify. Для Nginx прикладным 25 MiB потребуется запас под multipart (например, `client_max_body_size 30m` только в конфигурации этого API). Этот релиз настройки VPS автоматически не меняет. Не увеличивать глобальные лимиты других приложений. Можно проверить сначала маленький пример из трёх слов.

## Совпадения

1. NFC, пробелы, регистр при поиске, отдельно тип/артикль/грамматическое число. Умлауты и ß не заменяются. У существительного согласованный начальный артикль отделяется; у выражения «der Reihe nach» остаётся частью текста. Отсутствие артикля не считается признаком глагола.
2. Книга, урок, пример и заметка не разделяют одну лексическую карточку на новые слова. Новое значение без уверенного совпадения перевода требует выбора; несколько кандидатов тоже требуют уточнения. Один совпавший перевод — подсказка `existing`, не разрешение автоматического слияния. Отсутствие совпадения не гарантирует лингвистическую уникальность.
3. Экспортированный доступный ID сверяется с немецким словом, типом, артиклем и числом. Разные подтверждённые ID омонимов остаются отдельными существующими карточками. Недоступный/несовпадающий ID — `choice`, без раскрытия чужой закрытой карточки.
4. Повторы внутри файла отмечаются со ссылкой на первую совпавшую запись. Разные переводы того же написания без подтверждённых ID требуют уточнения. Дополнительные книги/материалы не удаляются: предпросмотр вообще ничего не записывает, будущий этап должен предложить правила их объединения.
5. Поиск на сервере ограничен опубликованными карточками и своими черновиками; ADMIN имеет те же ограничения. Не выдаются авторы, чужие словари, заметки или личные переводы. `inDictionary` относится только к текущему аккаунту.
6. Чтение — RepeatableRead + `SET TRANSACTION READ ONLY`. Поиск пачками до 100 условий; максимум 20000 доступных кандидатов. Ответ ограничен 25 MiB; для одного слова показаны до 5 кандидатов и по 3 фрагмента переводов до 160 символов; `moreCandidates` сообщает о дополнительных совпадениях. В UI страницы по 25 записей.

## Проверки и выпуск

Backend: весь набор words 121 тест перед последними уточнениями; после уточнений 10 HTTP-тестов предпросмотра и build повторно. Frontend: 182 клиентских теста, lint/build, изолированная сборка без чужих локальных правок. Дополнительно проверены настоящая выгрузка 3734 записей / 3751 пример / 626 вариантов форм и поиск по рабочей Neon строго READ ONLY; сводка без карточек хранится в приватной рабочей папке, не Git. Браузер использует синтетический файл и тестовую БД; это не приёмка нового API на VPS.

Миграция не нужна. Владелец обновляет backend под wortkarten:

```bash
(
  set -e
  cd /home/wortkarten/apps/german-vocab-backend
  git pull --ff-only
  npm ci --include=dev
  npm run build
  pm2 restart wortkarten-api --update-env
)
```

Netlify обновляет frontend из Git. В Настройках скачать пример, выбрать этот CSV в «Проверить файл перед импортом» и запустить проверку. Проверить группы результатов; новых слов в словаре после этой операции быть не должно.

## Следующий этап записи

Выбор карточки/отдельного значения, предварительный отчёт личных конфликтов, явное подтверждение, повторная серверная проверка и идемпотентный пакет. Только затем создание новых pending-карточек и привязка существующих без перезаписи общих полей, сброса прогресса или архива. Личные уроки по книгам ещё требуют отдельного решения модели; нельзя молча изменять общий источник или терять импортированный номер урока. Добавление XLSX должно использовать ту же серверную проверку, с отдельными лимитами распаковки и ячеек. Это открытые пункты, не функции данного релиза.
