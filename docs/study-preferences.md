# Настройки обучения и календарный день

GET/PATCH `/api/v1/users/me/preferences` теперь возвращают interfaceLanguage,
translationLanguage, timeZone, dailyGoal. PATCH меняет только переданные поля.
AuthGuard определяет владельца; ADMIN не управляет чужими настройками.
Неизвестные поля тела отклоняются, ответы no-store. Auth payload не расширялся:
учебные настройки читаются отдельным GET и не подменяют identity/role в клиенте.

timeZone — поддерживаемое Intl имя часового пояса, канонизируется сервером;
числовые смещения, пустые строки, null, неизвестные зоны и строки >100 запрещены.
dailyGoal — JSON number, целое 1–500. Строки, дроби и null запрещены.
Невалидное поле отклоняет весь PATCH, частичной записи нет.

Миграция `20261101200000_add_study_preferences` добавляет к users две колонки:
timeZone DEFAULT 'UTC', dailyGoal DEFAULT 10, обе NOT NULL; SQL CHECK диапазона
цели. Старые аккаунты получают эти значения. Существующие поля и записи не
удаляются и не преобразуются. Prisma 6.19.3 и зависимости не менялись.

GET `/study/progress` читает настройки и прогресс в одной RepeatableRead
транзакции и добавляет timeZone, dailyGoal, studyDate (YYYY-MM-DD).
studiedToday — число разных доступных слов текущего личного словаря, у которых
lastReviewedAt принадлежит сегодняшней календарной дате выбранного пояса и не
находится в будущем. Используются уже выбранные progressRows; дополнительная
выгрузка истории не нужна. Локальная дата определяется через Intl, без границ
с фиксированным 24-часовым сдвигом. Повтор одного слова/Idempotency-Key не
увеличивает дневное число разных слов; SRS по-прежнему реагирует на новые ответы.
Убирание слова из текущего словаря убирает его из активного дневного счётчика,
но не уничтожает прогресс/историю. Это не число всех попыток и не снимок активности.
Смена пояса меняет группировку «сегодня», не меняя timestamps и интервалы SRS.

54 study-теста, 37 languages-тестов и build прошли. Покрыты полуночь, разные
пояса, 23/25-часовые сутки, дробное смещение, повторы, приватность/отвязка,
границы цели, отсутствие частичной записи, независимость настроек и аккаунтов.
HTTP использует AppModule с mock Prisma, а не настоящий PostgreSQL.

Перед Deploy нового backend требуется применить эту миграцию к той же демо-БД.
Build/start не запускают миграции. `npx prisma migrate deploy` выполняется только
после проверки DATABASE_URL, ветки и списка ожидающих миграций. Основная Neon
main требует отдельного согласия. Проверка live-миграции описывается отдельно;
успех mock-тестов не означает, что схема реальной БД уже обновлена.

## Применение к демо-БД

01.11.2026 миграция применена только к подтверждённой ветке Neon «миграцион».
Проверены совпадение endpoint/database/schema и единственная ожидающая миграция.
После migrate deploy проверены UTC/10 для существующих аккаунтов. Контрольные
суммы всех прежних полей и количества 10 таблиц совпали до/после: 2 пользователя,
16 слов, 4 примера, 16 личных связей, 21 тренировка и 7 записей прогресса.
Основная ветка main не затрагивалась. Публичные сервисы требуют отдельного Deploy.
