# Импорт Excel/XLSX — 19.11.2026

## Что доступно пользователю

В Настройках → Мои данные → Проверить файл перед импортом доступны CSV и Excel `.xlsx`. Для Excel используются те же колонки, что и в CSV-шаблоне: открыть шаблон через импорт UTF-8/разделитель «;», заполнить и сохранить в формате XLSX. Сохранить названия колонок в первой непустой строке. До 25 МиБ файла и 10000 записей. Экспорт словаря по-прежнему CSV.

Проверка → выбор совпадений/значений → подготовка → модальное подтверждение → сохранение порциями и отчёт. Форматы используют один алгоритм доступности карточек, нормализации, дублей и сохранения. Повтор слова между CSV и XLSX также проверяется. В подготовленном пакете остаётся точный хеш исходного файла и решений; иной файл с тем же Idempotency-Key отклоняется. Аккаунты, общие карточки, личные данные и прогресс обрабатываются по [прежнему контракту](dictionary-import-save.md).

В первой версии один заполненный видимый лист. Пустые листы и строки с одной разметкой пропускаются; несколько непустых листов, включая скрытые, отклоняются понятным сообщением. Скрытые строки и столбцы внутри выбранного листа читаются: перед загрузкой нужно проверить весь лист. Номер в отчёте — последовательный номер записи после заголовков и пропуска пустых строк, а не физический номер строки Excel.

Читаются обычный текст/inline/shared strings и rich text, переносы, Unicode/Excel escapes, числа и логические true/false. Формулы, объединённые ячейки, типизированные даты и ошибки отклоняются; формулы предварительно заменить значениями. Форматирование чисел/дат не интерпретируется: текстовые поля хранить как текст, уроки — целыми числами. Старый `.xls`, `.xlsm`, пароли, произвольные названия колонок и выбор листа в интерфейсе пока не поддерживаются. Литеральный текст, начинающийся с «=», не выполняется как формула.

## Сервер

- `/dictionary-import/config` version1/readOnly сообщает `formats: [csv,xlsx]`; старые клиенты CSV продолжают работать.
- multipart `/preview` и `/prepare` принимают оба расширения, сверяют расширение с сигнатурой, проверяют размер. MIME от браузера не считается доказательством формата.
- `parseDictionaryFile` используется обоими этапами. Разобранная таблица проходит существующий CSV/DTO-валидатор, поэтому поля и правила одинаковы. Неверные заголовки Excel не превращаются в неизвестные служебные поля.
- ZIP читается последовательно в память, без извлечения на диск: yauzl3.4.0 lazyEntries/validateEntrySizes плюс проверка фактического размера и CRC. До512 элементов,64 МиБ суммарного заявленного распакованного размера,32 МиБ на часть. Запрещены неоднозначные/повторные пути, шифрование, макросы и встроенные объекты.
- XML sax1.6.1 strict, DTD запрещён. Внешние workbook relationships отклоняются; сетевые адреса не запрашиваются. Ограничены вложенность, атрибуты, число узлов и длина значений. XML разбирается порциями с передачей управления event loop; до двух одновременно и15сек на разбор. Дополнительно до600000 ячеек,16 листов и200000 shared strings.
- Никаких новых миграций, env-переменных, фоновых задач или production-записей для реализации не требуется. Схема CSV-сохранения уже применена отдельно 18.11.

Поведение библиотек сверено с их первичной документацией: [yauzl](https://github.com/thejoshwolfe/yauzl#readme), [sax-js](https://github.com/isaacs/sax-js#readme). Зависимости закреплены в package-lock; производственные библиотеки не выполняют Excel-формулы.

`npm run test:words` включает парсер и HTTP: текст, shared/rich strings, числа/boolean, переносы, sparse cells, единственное/множественное число, обязательные формы, разные значения/повторы, расширения, формулы с cached values, объединения, DTD, повреждённые ZIP/XML, внешние targets, макросы, лимиты строк/ячеек/распаковки. Весь набор words:136 тестов; backend build прошёл.

`test/xlsx-save.integration.cjs` работает только на `127.0.0.1:55439/postgres` и требует marker schema `wortkarten_import_test`. Запуск после `npm run build` с WORTKARTEN_IMPORT_TEST_URL, на новой синтетической копии текущей схемы; datasource production отвергается. Проверяет настоящий Prisma/SQL: XLSX preview → prepare → apply, повтор ключа/курсора, существующая карточка без перезаписи, личные книги/уроки, примеры и формы, изоляция аккаунта, запрет дубля через CSV после XLSX. PGlite-стенд не является проверкой всех конкурентных расписаний реального PostgreSQL.

Frontend:193 клиентских теста, lint/build на чистой копии без посторонних правок верстки. Браузер: синтетический вход + настоящий локальный SQL; файл с формулой получает понятную ошибку, исправный XLSX даёт все5категорий, выбор значения, модальное подтверждение и итог2новые/2существующие/1повтор/1пропуск. Проверены мобильные ширины320/390. Это локальная проверка, не подтверждение выпуска/Google/SRS на публичном сайте.

## Выпуск

Backend владелец обновляет вручную на VPS: `git pull --ff-only`, `npm ci --include=dev`, `npm run build`, `pm2 restart wortkarten-api --update-env`. `npm ci` нужен для новых библиотек. Netlify получает frontend из Git. Новая форма показывает XLSX только если backend объявил формат; при старом backend остаётся CSV. Миграцию повторять не нужно.

Приёмка публичного XLSX завершена владельцем 19.11.2026: предпросмотр 52 записей (38 новых, 8 найденных, 6 требующих выбора, 0 повторов и ошибок), затем подтверждённое сохранение. Владелец нашёл ratsam в своём словаре и сообщил о 38 новых карточках на модерации. Итог по выбору шести неоднозначных строк отдельно не сообщён. Экспорт обоих CSV истории также принят владельцем. Дальнейшие задачи — по актуальному roadmap; почта остаётся отложенной.
