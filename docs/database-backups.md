# Копии базы Wortkarten

Скрипт `scripts/backup-database.cjs` сохраняет постоянные данные приложения вместе
с аккаунтами, статусами публикации, переводами, примерами, связями и прогрессом.
Чтение идёт в одной Repeatable Read транзакции READ ONLY. Никакие миграции или
запросы записи к исходной БД он не выполняет.

Нужен Node22 и установленные зависимости из lockfile, включая Prisma CLI6.19.3.
CLI используется для генерации SQL из модели, не для изменения БД. Host нужно
указать явно: это защищает от случайной копии другой базы из старого окружения.

```sh
node --env-file=.env scripts/backup-database.cjs --expect-host YOUR_NEON_HOST --directory /private/backups/wortkarten-YYYY-MM-DD-HHMM
```

В Windows вместо `/private/backups/...` указать собственный абсолютный путь.
В окружении с уже заданным DATABASE_URL флаг Node --env-file не нужен.
Полную строку подключения не помещать в аргументы или Git. Каталог вывода должен
быть новым и находиться вне checkout; существующую копию скрипт не перезаписывает.

Результат:

- snapshot.json: все данные таблиц и метаданные схемы в одном согласованном состоянии;
- schema.sql: SQL модели приложения;
- restore-empty-database.sql: схема, дополнительные CHECK constraints, данные и история миграций;
- manifest.json: количества записей и SHA-256 файлов/таблиц.

Копия содержит хеши паролей и сессий. Хранить её в защищённом месте вне Git,
предпочтительно также на отдельном зашифрованном носителе/хранилище. Файлы получают
режим0600 там, где ОС его поддерживает; Windows использует права родительской папки.
В консоль выводятся только путь, host и количества, содержимое аккаунтов не печатается.

SQL предназначен ТОЛЬКО для новой пустой PostgreSQL БД. В начале есть проверка,
которая отклоняет восстановление при существующих таблицах public; весь файл
выполняется одной транзакцией. В production этот файл автоматически не запускается.
Создание копии не проверяет восстановление само по себе: manifest по умолчанию
содержит restorationTested:false. Проверку делать в отдельной БД, сравнивая SHA-256
содержимого всех таблиц и ограничения. После восстановления сменить истёкшие/старые
сессии и перепроверить доступы перед открытием новой БД пользователям.

Скрипт рассчитан на текущие16 таблиц приложения. При добавлении модели/таблицы
он остановится с несовпадением списка: обновить список и порядок зависимостей,
проверить SQL и восстановление до использования новой версии.

Это ручная копия в момент запуска, не настроенное ежедневное расписание.
При переносе на VPS отдельно настроить регулярное копирование вне сервера,
контроль ошибок и периодическую проверку восстановления. Временная ветка Neon
с автоудалением не подходит как единственное место хранения рабочих данных.
