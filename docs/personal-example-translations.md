Реализовано в коде 24.11.2026. Миграция `20261124120000_add_personal_example_translations` **применена к рабочей Neon с отдельного согласия владельца 24.11**; свежая копия восстановлена, сохранность прежних данных подтверждена. Обновление backend на VPS и публичная приёмка нового редактора ещё впереди.

## Поведение

В примере личного словаря появилась кнопка «Мой перевод примера». Пользователь задаёт до 1000 символов на выбранном языке содержимого. Перевод принадлежит только ему, не проходит общую модерацию и не меняет общий пример/общий перевод/чужие словари. Используется в личном словаре и тренировках; выбранный язык не заменяется русским. После очистки поля и сохранения возвращается актуальный общий перевод того же языка либо «Перевод отсутствует». Изменение сразу обновляет карточку и кэш примеров тренировки без перезагрузки.

Отметка «Мой перевод примера» отличает личный вариант. Общие translations остаются общими: форма ADMIN не получает личный текст как значение общего поля. Если немецкое предложение изменилось, старый личный вариант сохраняется, но перестаёт подставляться. UI сообщает об изменении и позволяет перечитать/подтвердить свой перевод для нового предложения.

## Данные и доступ

Миграция `20261124120000_add_personal_example_translations` создаёт только таблицу personal_example_translations и индекс. Ключ userId/exampleId/language, text и sourceGerman по VARCHAR(1000), revision, timestamps; внешние ключи на users и word_examples с CASCADE. sourceGerman — снимок предложения, для которого сохранён перевод. Снятие слова из личного словаря сохраняет личный материал, но скрывает его до повторного добавления (как личные заметки/переводы слов). Полное удаление примера/аккаунта удаляет связанные личные переводы. Удаление из словаря не стирает общий пример.

GET/PUT `/api/v1/words/:id/examples/:exampleId/personal-translations/:language`, AuthGuard, Cache-Control no-store. Владелец определяется из сессии, userId в payload не принимается. Нужны текущая личная связь со словом и доступность PUBLISHED либо собственное авторство, даже для ADMIN. exampleId должен относиться к тому же wordId. Архив допускает чтение/редактирование личного перевода.

GET возвращает wordId/exampleId/language, текущее german/commonText, личные text/revision/sourceGerman либо null, stale. PUT требует text, revision из GET (null для отсутствующего), sourceGerman с текущим немецким предложением. Пустой нормализованный text удаляет только собственный перевод выбранного языка. Несовпавшая revision или изменившееся предложение — 409, нет молчаливой перезаписи. Serializable-транзакции используют существующий повтор конфликтов; условные update/delete проверяют revision. Родительская принадлежность и доступ проверяются в той же транзакции.

Представление делает один пакетный запрос по владельцу, языку и примерам доступных личных слов. В WordExamples.list персональный вариант также показывается только при личной принадлежности; библиотека/чужие аккаунты не получают чужие данные. GET/PUT не возвращают список чужих переводов. Тексты остаются обычным текстом, не HTML.

## Совместимость и CSV

До миграции обнаружение таблицы через to_regclass возвращает false: словарь/общие примеры продолжают работать, кнопка скрыта, прямой новый endpoint даёт 503 (или 404 для недоступного примера). personalExampleTranslationsEnabled передаётся с личными карточками; клиент старого API без флага также скрывает редактор. Настройки/прогресс/SRS и версия Prisma не меняются.

В CSV-экспорт добавлена необязательная колонка `personal_example_translations_json`: массив {exampleId,german,language,text} со снимком исходного немецкого текста. Экспортируется только пользовательский материал. Версия CSV 1 и прежние колонки сохранены; прежние шаблоны по-прежнему принимаются. Заполнять JSON вручную для обычного импорта не требуется.

Импорт валидирует языки, форму/размер массива и поля; userId/посторонние ключи запрещены. Привязка только к примерам выбранного слова: сначала id плюс совпавший немецкий текст, иначе единственное совпадение немецкого предложения в этой карточке. ID из файла не даёт выбрать чужой пример. Для новой карточки новые id восстанавливаются по уникальному предложению. Ничего не дописывается в общий пример, если сопоставления нет. Неоднозначные/устаревшие примеры дают `personal_examples_unmatched`; отличающийся уже существующий личный вариант — `personal_examples_conflict`. Существующий текст не перезаписывается. Предупреждения попадают в предварительный план для выбранных существующих слов и в итоговый отчёт; для создаваемых слов сопоставление выполняется после создания примеров. Новый импорт с непустыми личными переводами до миграции отклоняется как недоступный, без их тихой потери.

## Проверки и выпуск

Прошли 153 words-теста и 3 дополнительных CSV-unit, 77 study, 41 languages, 242 клиентских теста, ESLint и сборки. После исправления кэша дополнительно собрана чистая будущая версия dashboard без постороннего форматирования владельца. Браузер на вымышленных данных: сохранение/перезагрузка/немедленное обновление карточки, пример в тренировке, очистка, 409 с сохранением черновика и блокировкой повторной записи, перечитывание, изменившееся немецкое предложение, RU/DE 390/320 без overflow, старый API с восстановленной сессией скрывает кнопку и сохраняет словарь. Это не реальный iPhone и не публичная приёмка нового редактора. Временные процессы/вкладки закрыты.

Отдельная новая PostgreSQL-совместимая база создана из предыдущей полной схемы, с синтетическими пользователями/словами/историей. Настоящий Prisma проверил миграцию: данные всех прежних 23 таблиц не изменились; дополнительно — доступ/ADMIN/языки, две правки одной revision, sourceGerman, личное представление, экспорт и восстановление CSV на новые exampleId, отсутствие перезаписи, предупреждения, unlink/relink, каскадное удаление. Ни .env, ни реальные пользовательские копии, ни production URL интеграционной проверкой не читались; Neon не затрагивалась. Это проверка синтетической локальной базы, а не свежей копии production.

Перед применением к основной Neon нужно отдельное согласие по backend AGENTS.md, свежая приватная резервная копия и проверка списка ожидающих миграций. Применять только согласованную миграцию; после — проверить новую таблицу и сохранность прежних данных. Затем обычный выпуск backend на VPS и frontend Netlify. Пока миграция не применена, функциональность безопасно выключена. При откате кода таблицу можно оставить: обратного удаления пользовательских переводов не требуется.

Приёмка: открыть пример личного слова, сохранить свой перевод, увидеть его в карточке/тренировке; второй пользователь видит общий. Очистка возвращает общий выбранного языка. Расширение каталога языков остаётся отдельной частью R16.
