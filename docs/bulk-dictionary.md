# Массовое добавление найденных карточек

Вкладка «Библиотека»: выполнить поиск, выбрать книгу и урок, нажать «Добавить все найденные (N)». N — число ещё не добавленных карточек среди найденных. Поиск применяется кнопкой «Найти»; пока введённый текст не применён, массовая кнопка недоступна. Книга и урок применяются сразу. Можно выбрать все книги/уроки либо карточки без книги/урока.

POST /api/v1/words/dictionary/bulk принимает { wordIds: string[] } — снимок всех найденных карточек. До 2000 уникальных ID, максимум 191 символ в каждом. Нужна обычная авторизация. userId/роль и другие поля из тела отвергаются ValidationPipe. Маршрут не зависит от роли ADMIN.

Сервер повторно выбирает только PUBLISHED из переданных ID. Неопубликованные, удалённые и неизвестные карточки объединяются в unavailableCount; их ID и содержимое не возвращаются. Даже администратор не добавляет через этот маршрут чужие pending-карточки. В одной Serializable-транзакции выполняется UserWord.createMany(skipDuplicates:true). Существующие связи не обновляются: сохраняются архив, избранное, revision, личные материалы и SRS. Повтор запроса безопасен, конфликт транзакций обрабатывает существующий WordAccessService.

Ответ: requestedCount, addedCount, alreadyInDictionaryCount, unavailableCount и wordIds (только актуальные опубликованные карточки). После успеха обновляются счётчики библиотеки и данные личного словаря/прогресса. Если карточку сняли с публикации, она убирается из текущего результата; итоговое сообщение сохраняется. При сетевой/серверной ошибке автоматического повтора мутации нет, кроме уже существующего однократного authenticated retry после 401. Пользователь может обновить библиотеку; повторное добавление не сбрасывает прогресс.

Фильтры касаются общих sourceBook/lessonNumber опубликованных карточек. Личные названия книг других людей не раскрываются. У одного слова пока один общий номер урока, отдельные уроки для разных книг не добавлялись.

Проверки: test:words — 83 теста, test:client — 150 тестов, lint frontend, build backend/frontend. Новые HTTP-тесты проверяют авторизацию, некорректный ввод/инъекцию личности, частично недоступную подборку, повтор, изоляцию словарей, сохранность архива/избранного/revision. Это настоящие Nest controllers/services с тестовым persistence, не проверка PostgreSQL-конкуренции.

Локальный браузер с отдельным mock API: книга+урок, ошибка 500 → обновление → успешное добавление, отключение повторной кнопки, мобильная ширина 390px без горизонтального переполнения. Реальные аккаунты и production Neon при проверке не использовались. Миграций нет. После публикации сначала дождаться backend, затем frontend, проверить через библиотеку на Render/новом хостинге.
